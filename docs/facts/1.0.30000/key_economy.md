## 1. 按键计划日志（keys_i<N>.jsonl）

每个运行目录、每个实例一个文件，每场一行（`combat_run` 的 planner 策略自动写，不需要 SSBOT_LOG_ALL）。每场约 25–45 KB（同一场的事件窗口决策日志约 1.5 MB）。

- **音符**（note）= 命令流里一个键的一次按下：该键的位连续为 1 的一段帧。每个 tick 把规划器选中方案的整条命令流（决定帧 d = f + 2 起，48 帧或自适应视野更长）按键拆成段，与上一 tick 仍未发出的音符匹配：
  - 从 d 开始、而上一帧发出的掩码里该键已按下的段 = 正在按住的音符的延续（只可能改松开帧）；
  - 其余段与未发出的音符一一配对，按下帧相差 ≤ 6 帧或两段重叠才算同一个音符，按下帧最近的先配；
  - 配上但按下 / 松开帧不同 = 一次改动（记一条历史）；没配上的旧音符 = 取消；没配上的新段 = 新音符，出生于本 tick；
  - 按下帧等于 d 的音符在本 tick 发出（executed）；迟到的 tick 跳过了某个未发出音符的按下帧 = 取消（"l"，从没发出）。
- 松开帧到了方案末尾还按着时记为负数（"至少按到 −r"）；之后的方案在这一帧之前松开才算改动，视野往前推本身不算。
- 实际按键：每个 STATE 的 `act.mask`（oracle 本帧锁存的掩码，含追赶的跳帧 STATE）的上升 / 下降沿，即游戏真正收到的按下 / 松开帧。发出的音符按"同键、锁存按下帧在发出帧后 0–4 帧内的第一个"配到实际按键（`match_actual`）。首批 6+7 场：发出的音符 100 % 配上，锁存比发出晚 0 帧的占 88–95 %，其余晚 1–3 帧（按住过滤的最短松开 2 帧、ACTION 迟到）。
- 监督器接管按键时（暂停机）只记发出的那一帧，音符标为 sup，统计时单列。
- 帧级抖动：相邻两个 tick 的方案都覆盖、尚未发出的每一帧上，某键的位变了 = 一次改动；同一帧上第二次及以后的改动必然是改回去 = 来回改（flip-flop）；正好撤销上一 tick 的改动 = 一 tick 来回改。

一行的字段：`ep, f0, f1, ticks, sup_ticks, view, notes, actual, flips`。`notes` 每项 `[键, 出生 tick 帧, 按下, 松开, 状态, 发出 tick 帧, sup, 历史]`，状态 x 已发出 / c 取消 / l 迟到取消 / o 结束时未发出 / h 日志开始前已按住；历史每条 `[tick 帧, 按下, 松开]`，取消为 `[tick 帧, −1, −1]`。`actual` 为每键 `[[按下, 松开], ...]`（松开 −1 = 结束时仍按着）。`flips` 为每键 `[改动, 来回改, 一 tick 来回改]`。

## 2. 指标（`ssbot.tools.key_economy`）

窗口 = 每场从 Boss 苏醒到结束（AttemptRecord f_wake–f_end）；HARNESS_FAIL 不计。

- 每秒按键数：锁存按键（`act.mask` 上升沿）÷ 战斗秒数（帧数 / 60），分键和合计；没有按键日志的旧运行从录像的 `act.mask` 读，结果相同。还给每键按住时长分布和"≤ 3 帧的点按"比例。
- 决定的按键 = 按下帧在窗口内的规划器音符；计划改动率 =（发出前被改过的 + 被取消的）÷ 决定的按键，也分键。发出后再改松开帧单列（按住时长的改动）。
- 提前量 = 第一次决定（出生 tick 帧 f）到发出的按下帧，帧；最小是 2（决定帧 d = f + 2，ACTION 的固定提前）。也给到锁存按下帧的提前量。
- 抖动：每秒改动、来回改、一 tick 来回改（按日志覆盖的 tick 时长算）。

## 4. 切换代价（`key_press` / `key_change`）

### 4.1 做法

- J 里加两项（剧本权重；DEFAULT_WEIGHTS 里没有 = 0 = 关，Bell Beast 剧本按 4.3 采用 0.05 / 0.1；`combat_run --key-cost P C` 覆盖）：`key_press` × 候选方案的按键数（命令流里每个键的上升沿，第一帧相对上一帧发出的掩码）；`key_change` × 与上一 tick 选中方案（按决定帧对齐）在两者都覆盖的帧上的差异：上升沿一边有一边没有各算 1（去掉、加上、挪动一个按下），下降沿不同各算 0.5（改松开）。
- **只在同一安全类里排序**：先照原样选（字典序 + 视野外检查），得到不加这两项的选择 i；再在与 i 的 (Hz, Hz_soft, U, S, 跳跃承诺, 宏承诺, 舒适余量, V, P, 首次接触帧) 完全相同的方案里，取扣分后 J 最大的 j。i 的视野外检查（tail）通过时，j 也必须自己通过（上一 tick 留下的 CONTINUE 按原规则算通过）；i 的检查失败时保留 i；没做检查时（FORCED_RISK、自适应长视野）直接取 j。所以不管权重多大，选中方案的 Hz / U / S / V / P、承诺和视野外结果都与不加时相同。`PlanResult.cls` / `cls_off` 给出两者的安全类。
- 宏承诺（下劈连招）的比较用不扣分的 J，扣分不会让一个宏被替换或保留。
- 开销：每 tick 一个 numba 循环（候选 × 帧），加上换了方案时一次单行的视野外检查；回放 2,998 tick：tick p50 5.18 → 5.24 ms，p99 13.08 → 12.98 ms（在噪声内）。

## 5. 按键轨道渲染原型（`ssbot.tools.key_track`）

- 离线：一场的按键计划日志 + 录像（竞技场小条）→ 每个游戏帧一张 PNG（640 × 720）→ ffmpeg libx264 60 fps。每个键一条轨道；音符在第一次决定的那一帧出现，6 像素 / 帧匀速下落，碰到判定线的那一帧 = 游戏锁存按下的帧（发出前按计划位置画，发出后按实际锁存帧），长度 = 按住时长，按住时缩进判定线；取消的计划留灰框直到那个时刻过去，挪动的计划在旧位置留 12 帧灰框；判定线上的彩色条 = 游戏此刻按着这个键。
- 样例在 `C:\ssbot\sandbox\key_track_sample\`：`off_i2_ep0`（关，运行 213031 实例 2 第 0 场，苏醒后 10–30 s）、`on_i3_ep0`（w1，运行 213033 实例 3 第 0 场）、`off_vs_on_side_by_side.mp4`（左关右 w1，两场不同的战斗），每个目录有 1,200 张帧图、mp4、notes.json，README.txt 是说明。
- 正式录像要叠在游戏画面旁边（DESIGN 正式运行一行）；这里只有轨道。因为大多数按键提前量只有 2 帧，大多数音符在判定线上方 12 像素处才出现；灰框多就是计划改得多，这正是视频里能看见的东西。

## 6. 下一步

1. 按键项只做"近似平局"的决胜：在同一安全类里只考虑 J（不含按键项）离最好的不超过 δ 的方案，再按按键项选，这样它拿去换的 J（含 risk）有明确上界，可以放心加大权重（w2 的受击就是没有上界造成的）。按同样的 A/B（≥ 100 场一组）定 δ。
2. 方向键微调：bot 的 2–3 帧方向点按占四分之一。站位项（stance）每 tick 都在奖励小挪动；可以把站位的死区（离站位 < 某距离不扣分）和按键项一起试。
3. 提前量：大多数按键当场决定，是因为候选方案都"从现在开始"，上一 tick 的计划只有 CONTINUE 一行保留。若视频里想看到音符提前出现，需要候选里有"保留上个计划的前半段、只换后半段"的方案。
4. "Boss ≤ 15 血、挨过打就不出刀"的 STUCK（U 规则把每一刀都当作可能的致命一击）：已作为单独任务提出。
5. 视觉视图（第二阶段）复测：日志和工具在 degraded 视图同样工作（决定帧同样是 f + 2），没跑过。
