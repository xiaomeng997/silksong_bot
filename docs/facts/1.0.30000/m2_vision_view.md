## 做法（全部是视觉可得的信息）

- **落铃路径来自轨迹**（`combat/bell_track.py`）：落铃从开始下落那一帧才绘制（`20261002_171806` i0_000：178 / 178 次首帧在 Air、y 13.74、速度 (0, −17)，写入注册表 `start`），竖直下落（FSM 置 vx 0），落地一次以 ±4 u/s、vy 30 弹向随机一侧，第二次触地沉入地面。所以路径由三个数决定：下落列 x（下落段检测的均值）、下落时刻（每个下落检测的高度在已知下落曲线上反解，取中位数，减半个物理步）、弹跳方向（首次触地后 x 漂移的斜率超过 5σ 且 ≥ 2 u/s 才定，之前两侧都算）。路径用注册表物理（50 Hz 步，从下落开始）按"距下落的时间"采样，时间余量照用 DET_SLACK_S，接触皮再加 3σ 的列 x 不确定度（σ 取视图位置噪声）。最近两次检测偏离模型 > 0.6 u（或 5σ），或 hero 在铃的攻击可达范围内出刀（可能拼刀改向，视图没有拼刀事件），就撤回，回到 self 模板。只用检测（visible_frac > 0），不用视图的速度。

## 2. 主角打铃的效果在视觉视图里建模（主要问题，8809999；M2 计划"效果已知的动作不能让危险区变大"）

- **改向规则（事实）：** DropBell FSM（`C:/ssbot/sandbox/m2_agent_notes/fsm_dropbell_m.txt`）：TINK RIGHT → vx = clamp(|vx|, 5, 10)；TINK LEFT → vx = −|vx| 再 FloatClamp(min −5, max −10)，即 |vx| > 5 时 −5、否则 **−10**；TINK DOWN → vy = min(vy, 0)；之后的落地弹向改向一侧（Bounce X = ±4）。oracle 实战录像 `20261002_171806`（74 场）共 95 次打铃（`vv_scratch/fx/tink_facts.py`）：侧砍 92 次，方向全部等于主角朝向（92 / 92，SlashAlt），速度 90 / 92 符合规则（另 2 次在看的 2 帧内已落地弹起，弹向 = 改向侧）；左向 45 次全是下落或 ±4 弹跳中的铃，全部变成 −10。**`pogo_targets.simulate` 原来把左向一律算成 −5**，oracle 视图的改向路线也错了，一并修正（`pogo_targets.tink`），并支持 TINK DOWN 和多次改向。
- **轨迹不再撤回：** `bell_track` 里主角在铃的攻击可达范围内出刀时，不再撤回精确路径退回 self 模板，而是保留"未打中"分支和每个可能改向时刻的"打中"分支（触碰帧所覆盖的物理步，每 2 步一个，中间由 ±0.02 s 时间余量覆盖；侧砍方向 = 朝向；视图分不出侧砍 / 上砍 / 下劈，上升段另加 TINK DOWN 分支）。之后的检测剪枝：两次超出 max(0.6 u, 5σ) + 3σ_列，或改向后检测的平均 x 偏差超过 max(0.25 u, 6σ_均值)；全部剪光才撤回；分支超过 48 个（连续两刀）也撤回。各分支的相对路径按分支缓存（与列 x 无关）。
- **规划器：** 视觉视图的铃目标默认打开（`SSBOT_VE_TARGETS=0` 关）：攻击铃（命中后坐、下劈弹起 + 0.5 s 冷却）和落铃（侧砍按改向规则走它的分支，下劈只在下落段算命中）。有未定分支的落铃不作为目标，任何攻击会碰到它某个分支的方案都判为不安全（`planner._ambiguous_bells`）。
- **核对：**
  - `bell_track_audit`（`171806` 4 实例 × 4 场，噪声种子 1，现在按视图的时间余量打分）：碰过的落铃 1,417 帧里撤回 0 次（之前全部撤回）；分支数 p50 5、p90 11、最大 18；中心误差超出接触皮的样本：未改向 49 / 103,804（0.05 %），在预报原点前已改向（有分支）25 / 10,022（0.25 %，最大 0.28 u，在视图余量 0.335 u 内）；原点之后才被打的 3,592 / 5,328 属于规划器自己的方案（由方案的打中分支建模，不是预报的事）；弹向判错 0 / 45,669。

## 7. 不改的项（理由）

- **狂暴剪枝加误检余量：** 在本轮的噪声模型里视图 HP 只会偏高（两轮实战 414,795 次决策 0 次低于真值）。`20261002_232157` 里 154 次狂暴决策时的真实 HP：75 有 52 次、70 有 37、65 有 39、60 有 14、55 有 4、50 有 8；加一次刀伤（5）的余量会让 34 % 的狂暴失去剪枝，加一次最大伤害（15）会让 83 % 失去，正是第二轮查明的 Rage Pos / Rage Antic 全程 FORCED_RISK。命中检测的误报率是 M3 感知指标（DESIGN §3.9.2 的混淆矩阵），有了实测值再定余量；在此之前把它列为已知假设。
- **铃爆锚点按 σ 放 ±3σ 副本：** 规则是 σ/√n 超过视图余量覆盖的 0.10 u 才放；Boss 单次检测 σ = 0.10，所以 n ≥ 1 时永远不触发，改了也不变。种子 23 的那次漏检（锚点偏 0.27 u）在 0.1 u 余量和实战余量 0.335 u 下都覆盖（§4 实测）。
