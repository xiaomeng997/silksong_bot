## 规划器：超过视野的长招（W4，2026-10-01 你的问题）

固定 0.8 s 视野的问题：前跳 → 冲刺 → 砍这种组合超过 0.8 s，收益（命中）落在视野外，规划器看不到，就不会选它（视野效应）。安全不受影响（每帧重查，只承诺视野内安全且留有退路的动作），影响的是打得好不好。W4 的做法：
- **宏动作：** 长组合作为一个原语，rollout 按它的全长加安全尾巴推演（例如 1.5 s），威胁预测也延长到同样长度。远期的支撑会变宽，所以这类宏只在 Boss 未来走向确定时（锁定在一个已知时长的长招或硬直里）才能通过安全检查，这正是人会用它的时机。
- **自适应视野：** Boss 进入时长已知的长招（例如 Bell Beast 的冲撞前摇约 0.6 s + 冲撞约 0.88 s）时，把视野延到招式结束加反应时间。
- **终点价值：** 推演终点按"是否处在惩罚位置、能否接上命中"打分，让铺垫动作也有分，在 savestate 批次上调参。
- **剧本里的已知惩罚：** "某招之后做某组合"直接写进 L3 剧本，规划器只负责验证安全。你的经验可以直接写成这种条目。
- **无敌帧：** rollout 记录下劈、弹反、受击后的无敌窗口，穿过攻击判定时不算命中；危险物和无视无敌帧的伤害照算。

## Bell Beast 的视觉前兆（你的经验，2026-10-02）

- 冒出前地面冒烟：**矮烟 = 冲撞**（Emerge Antic C），**高烟 = 跳砸**（Emerge Antic L），约提前 1.0 s；烟的位置 = 冒出位置（左 / 右）。
- 扔铃铛（Burst）前：地面**窄烟**（Burst Pos / Burst Antic，冒出 x 81.2–91.2）。
- 天上掉铃铛前：天花板处**最窄的烟**，指示哪一个铃会掉。
- 打法：Boss 扔铃铛时可以站在它旁边砍两刀，再躲铃铛（等在冒出点旁边）。
- 打法：Boss 在地面冲撞时用下劈（跳起、踩在它背上弹起，同时躲过冲撞）；Boss 从头顶跳过时用上砍，不是平砍。
- 前兆阶段能预测跳砸的完整轨迹：只从两个固定点起跳，相对起跳点的路径偏差 < 0.6 u。
- 铃铛是游戏专门设计的下劈踩点（钟屋、蚀阶满地都是）：Bell Beast 的落铃 / 攻击铃在下落段可踩（快速上升段大概不行，按阶段核实），下落中踩铃弹走是标准逃生手段；跑图（M4，S17 Blasted Steps 等）也要把连续踩铃当作基本移动动作。做成通用的"可踩目标"表（类型 → 可踩阶段、接触形状、弹起参数），战斗和跑图共用。
- 之前模拟视觉层没用这些线索：烟尘是纯视觉特效，没有碰撞框和血量，mod 不导出，所以训练数据里不存在；Boss 钻地时一律按"看不见、什么都可能"处理。原计划等 M3 在影子模式里实测前兆（tell_lead_vision），M2 的模拟因此偏悲观。现在先截图确认，再加入可见阶段表，并单独测量有无前兆的差别。

## 视觉条件下的迎面下劈（你的判断，2026-10-02 晚）

- 现象：degraded_dust 实战每次冲撞只踩中 0.19 次（oracle 0.97，迎面 22 / 24）；bot 很少敢迎面下劈。
- 你的判断：**只要大黄蜂高度对，水平误差只要比 Boss 窄就能劈中**。冲撞身体长约 10.9 u，以 16–28 u/s 从下方经过约 0.4–0.7 s；延迟和噪声造成的 0.8–1.4 u 水平误差只影响 Boss 两端，迎面下劈的精度要求在竖直方向（顶部残差实测 0.17 u）。
- 下一轮视觉链第一优先：
  - 下劈门槛按这个几何来判：在有效帧内，下劈多边形与 Boss 顶部重叠，对所有延迟假设（2 / 3 / 4 帧）都成立；水平余量只收缩 Boss 两端，不要求踩中某一瞬间的前沿。
  - 核查一个疑点：视觉门槛把 Boss 框截断在"本阶段最早可能结束"的时刻（最短记录时长）。迎面下劈发生在冲撞后段，可能正是被这一截断挡掉的；冲撞的结束条件应换成它真实的（位置）条件。
  - 冲撞开始后，用全部检测帧拟合这一次的起始时刻和初速度（路线确定、不变招），用拟合残差定余量；跳砸单独处理。
  - 按迎面 / 背后分别统计视觉条件下的出手次数和命中率（spike_audit 目前固定 oracle 视图回放，要加 --view）。

## 降低风险的动作（你的批评，2026-10-02 晚）

- 你的话："拼刀失败也安全的情况根本不需要拼刀。打铃铛一下减少一半危险区的生意 bot 都不会做。"
- 数据：打落铃改向每场二阶段 oracle 视图 2.49 次，模拟视觉视图 0.4 次（20261002_223925）。原因：视觉视图的精确铃路（bell_track）在主角可能碰到铃时撤回，退回宽模板，于是"打铃"在规划器眼里是增加危险而不是减少。改向是确定的（远离出刀方、固定速度），视觉视图里同样能推算。
- 原则：凡是能缩小危险区的机制（打铃改向、拼刀弹开飞行物、杀掉召唤物、拼刀无敌 / 取消后摇后脱身），都要在**两个视图**的推演模型里体现，规划器才会因为"更安全"（第一优先级）去做，而不是把它当成纯代价。拼刀规则的修订见 DESIGN §3.5.6。
- 事后审计补一项：在录像里统计"有降低风险的动作可用（打铃、拼刀）而 bot 没做"的时刻，按视图分开（opportunity_audit 扩展）。
- 下一轮视觉链：视觉视图里打铃改向后的路线按确定规则推算（不撤回），验收看二阶段改向次数和落铃受击数。
- 一致性原则（你的话："打到铃铛会让安全区增加，如果模型算成更小，说明算的不对"）：效果已知的动作不能让危险区变大。视觉视图在"可能碰到铃"时退回宽模板，是丢掉了信息：正确的保守做法是两个窄分支的并集（打中 → 改向后的确定路线；没打中 → 原路线），看到铃的运动改变后收成一支，始终比宽模板小。写成两个视图都跑的属性测试和实战监视：对每次打铃（录像 + 模拟），打铃方案的危险区（主角周围、打铃后 1 s 内）不得大于不打铃方案；违反就是模型错误，记录并修，而不是让规划器回避打铃。同一检查推广到拼刀弹开飞行物、杀召唤物等所有缩小危险的机制。
- 拼刀（你的补充）："拼刀非常帅；有的招近身很难躲又出得频繁，一律躲就永远别想近身打怪。" Forum 先做：从采集数据和 mod 导出的可拼刀位列出每种敌人可拼刀的招；推演模型加入拼刀效果（对方攻击作废、0.15 s 拼刀无敌、取消后摇）；按整场 A/B（拼刀开 / 关）决定用不用（DESIGN §3.5.6 修订）。

## 低血量：先回血，回不了才退出（你的修订，2026-10-03 早）

- 起因：暂停链（10bfb66）把 Q1 改成"血量 ≤ 下一击伤害、Boss 在地下且支撑确认为空时立即退出"；之前 bot 会趁这个空档 Bind 继续打。
- 你的意见："没危险的时候先加血，或者跑到 Boss 到不了的地方加血。" 为什么在没危险时退出：暂停只在部分帧有效（受击冻结、后坐、拼刀冻结会吞掉），所以退出要在保证能暂停的时候开始；但这不等于安静时该退出，安静的窗口首先是回血的机会。
- 修订（DESIGN §3.7.4 Q1）：① 原地 Bind（Bind 提交条件满足时）；② 否则去已核验的安全点 Bind（覆盖图之外，路径在支撑下安全）；③ 都不行才退出。丝 < 9 时只能 ③。
- 安全点（你的经验）：Forum 左墙顶；**Lace 2 和歌后的场地：顺着右墙爬到顶，再往上二段跳，那里永远打不到**。我们的路线默认没有二段跳（Faydown 只在 A/B 里），这条是给 Faydown 加分的证据：路线调研和 K1 要把"有二段跳的安全点"算进价值。每个场地的安全点都用覆盖图核验后才进剧本。
- 下一轮：改暂停链的 Q1 分支（加 ① ② 的判断），回放所有 Q1 退出，统计其中本可以回血的比例。

## 预测必须可检验（你的建议，2026-10-02）

- 起因：你在实战画面里看出攻击没打提前量（下劈、上砍、丝矛）、砍中后的后坐让第二刀落空。系统自己没发现，因为它只核对了 Boss 的危险区域（离线覆盖率 100%）和主角移动轨迹，没核对主角攻击的结果。
- 方法：规划时把选定方案的预测记下来（每一刀的生效帧、那几帧 Boss 的预测位置、是否命中及概率、对主角的效果、之后的轨迹）→ 回放时用命中事件和实际位置逐条核对（混淆矩阵、概率校准、时机偏差、位置残差，最差个例）→ 固定偏差在一部分场次上拟合、另一部分验证；缺项补模型；无法消除的随机性放宽概率或余量 → 实战中残差进入监视器，超阈值时降低信任、收紧打法。
- 适用于所有模型和所有 Boss，作为标准做法；威胁一侧的概率预测同样核对。
- 盲区（你的例子：Boss 从头顶跳过时 bot 跳起平砍、不会跳起上劈）：自检只核对"选中的动作预测得准不准"，看不到"没选的动作是否更好"。补充**事后机会审计**：录像里 Boss 的实际轨迹已知，离线把每个时刻所有安全的攻击选项都模拟一遍，统计"本能打中却没打"的错过率（按 Boss 招式和攻击类型），并以你的录像为标杆比较每招的命中数。

## 机制发现（2026-10-02，你的问题："这种机制机器人能自己探索发现吗"）

- 规划器只会用模型里有的效果：模型不知道"踩中会弹起""打铃铛能改弹跳方向"，就永远不会下劈、只会躲铃。所以要有一个自动发现机制的环节，而不是只靠人写战术。
- 做法：互动效果挖掘工具（effect_miner）在所有录像上统计"攻击碰到某物体（按类型和阶段）之后，物体和主角的运动、状态、伤害有无显著变化"，与同条件未接触的情况对比，标出显著效果；数据里样本不足的组合列为待做的定点实验（在 savestate 里用每种攻击、在每个阶段去碰每种物体）。确认的机制写进推演模型，规划器在有利时自动使用（安全检查照常）。
- 你的经验是最快的捷径：直接告诉实验该测什么。
- **每个新遭遇战的标准发现流程**（2026-10-02 起）：① 读游戏属性（mod 导出的每个伤害框的拼刀 / 强制弹反 / 反击位、可踩层、弹反组件）；② 在采集录像上跑互动效果挖掘（每种攻击 × 每种物体 × 每个阶段：被弹回 / 打掉 / 穿过、主角弹起 / 后坐 / 弹反无敌 / 冻结）；③ 样本不足的组合做定点实验（采集模式，必要时补做无敌模式并交叉核对）；④ 确认的机制写进推演模型。弹反照 DESIGN §3.5.6 白名单（观测到过拼刀、视觉成功率 ≥ 99.5%、失败也不靠面具能活、谨慎模式和准备暂停时禁用）。你提到的线索（如飞镖可弹开、很多攻击可弹开）优先做定点实验。
