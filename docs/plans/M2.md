## 规划器：超过视野的长招（W4，2026-10-01 你的问题）

固定 0.8 s 视野的问题：前跳 → 冲刺 → 砍这种组合超过 0.8 s，收益（命中）落在视野外，规划器看不到，就不会选它（视野效应）。安全不受影响（每帧重查，只承诺视野内安全且留有退路的动作），影响的是打得好不好。W4 的做法：
- **宏动作：** 长组合作为一个原语，rollout 按它的全长加安全尾巴推演（例如 1.5 s），威胁预测也延长到同样长度。远期的支撑会变宽，所以这类宏只在 Boss 未来走向确定时（锁定在一个已知时长的长招或硬直里）才能通过安全检查，这正是人会用它的时机。
- **自适应视野：** Boss 进入时长已知的长招（例如 Bell Beast 的冲撞前摇约 0.6 s + 冲撞约 0.88 s）时，把视野延到招式结束加反应时间。
- **终点价值：** 推演终点按"是否处在惩罚位置、能否接上命中"打分，让铺垫动作也有分，在 savestate 批次上调参。
- **剧本里的已知惩罚：** "某招之后做某组合"直接写进 L3 剧本，规划器只负责验证安全。你的经验可以直接写成这种条目。
- **无敌帧：** rollout 记录下劈、弹反、受击后的无敌窗口，穿过攻击判定时不算命中；危险物和无视无敌帧的伤害照算。

## Bell Beast 的视觉前兆（你的经验，2026-10-02）

- 冒出前地面冒烟：**矮烟 = 冲撞**（Emerge Antic C），**高烟 = 跳砸**（Emerge Antic L），约提前 1.0 s；烟的位置 = 冒出位置（左 / 右）。
- 扔铃铛（Burst）前：地面**窄烟**（Burst Pos / Burst Antic，冒出 x 81.2–91.2）。
- 天上掉铃铛前：天花板处**最窄的烟**，指示哪一个铃会掉。
- 打法：Boss 扔铃铛时可以站在它旁边砍两刀，再躲铃铛（等在冒出点旁边）。
- 打法：Boss 在地面冲撞时用下劈（跳起、踩在它背上弹起，同时躲过冲撞）；Boss 从头顶跳过时用上砍，不是平砍。
- 前兆阶段能预测跳砸的完整轨迹：只从两个固定点起跳，相对起跳点的路径偏差 < 0.6 u。
- 铃铛是游戏专门设计的下劈踩点（钟屋、蚀阶满地都是）：Bell Beast 的落铃 / 攻击铃在下落段可踩（快速上升段大概不行，按阶段核实），下落中踩铃弹走是标准逃生手段；跑图（M4，S17 Blasted Steps 等）也要把连续踩铃当作基本移动动作。做成通用的"可踩目标"表（类型 → 可踩阶段、接触形状、弹起参数），战斗和跑图共用。
- 之前模拟视觉层没用这些线索：烟尘是纯视觉特效，没有碰撞框和血量，mod 不导出，所以训练数据里不存在；Boss 钻地时一律按"看不见、什么都可能"处理。原计划等 M3 在影子模式里实测前兆（tell_lead_vision），M2 的模拟因此偏悲观。现在先截图确认，再加入可见阶段表，并单独测量有无前兆的差别。

## 视觉条件下的迎面下劈（你的判断，2026-10-02 晚）

- 现象：degraded_dust 实战每次冲撞只踩中 0.19 次（oracle 0.97，迎面 22 / 24）；bot 很少敢迎面下劈。
- 你的判断：**只要大黄蜂高度对，水平误差只要比 Boss 窄就能劈中**。冲撞身体长约 10.9 u，以 16–28 u/s 从下方经过约 0.4–0.7 s；延迟和噪声造成的 0.8–1.4 u 水平误差只影响 Boss 两端，迎面下劈的精度要求在竖直方向（顶部残差实测 0.17 u）。
- 下一轮视觉链第一优先：
  - 下劈门槛按这个几何来判：在有效帧内，下劈多边形与 Boss 顶部重叠，对所有延迟假设（2 / 3 / 4 帧）都成立；水平余量只收缩 Boss 两端，不要求踩中某一瞬间的前沿。
  - 核查一个疑点：视觉门槛把 Boss 框截断在"本阶段最早可能结束"的时刻（最短记录时长）。迎面下劈发生在冲撞后段，可能正是被这一截断挡掉的；冲撞的结束条件应换成它真实的（位置）条件。
  - 冲撞开始后，用全部检测帧拟合这一次的起始时刻和初速度（路线确定、不变招），用拟合残差定余量；跳砸单独处理。
  - 按迎面 / 背后分别统计视觉条件下的出手次数和命中率（spike_audit 目前固定 oracle 视图回放，要加 --view）。

## Forum 打法问答（你的回答，2026-10-03 傍晚；问题见 forum_planner_plan.md）

- 多段攻击一套掉几格、能否中途脱出：**让 bot 自己实测**（R0 / R1 从数据统计每条连段的最大次数和伤害）。
- 防御姿态（Minister 格挡、Reed 防御）：被打中后有**固定反击动作**；你不小心打到时会跑出反击范围；反击应该可以拼刀。
- 拼刀：最容易拼的是**小铃铛**；你自己基本不拼刀，但希望 bot 拼刀（帅）。按 DESIGN §3.5.6 修订：建模后整场 A/B 决定。
- 冲刺斩：**偷丝怪（Clawmaiden）用冲刺斩很好打**，它正好控制在冲刺斩的距离、跟着你移动，走着追不上；其他怪用冲刺斩也好，但不用也能打到。**飞针撞到怪自己不受伤**（运动学测试里核实）。
- 站位：**天上飞的怪通常往斜下打，站在它正下方挨打概率大大减小**；收割者下劈范围巨大，在有些怪头顶一直下劈也不错。
- 击杀顺序：**抽丝怪（Clawmaiden）最先打**；铃铛怪（Bellbearer）和召唤四个飞虫的怪（Maestro）不会来撞你，在远处可以先不管；剩下追着你打的怪要防止聚拢，先打追你的。
- 小铃铛可以打走，但在它上面下劈大概率弹不起来。
- 诱导：让 bot 在各招攻击边界附近试（采集策略按每招的触发距离 / 判定边界取样，统计站在哪里会诱出哪一招）。
- 四个决定按建议：M2 阶段 Forum 每帧规划 p99 约 15 ms 可接受（3–4 ms 留到视觉阶段）；多段攻击按实测的最大连段伤害计 h；做训练用的"从第 N 波开始"mod 命令；字典序不改（站位只影响安全选项之间的选择）。
- 没答的（挂墙回血、终局慢动作、加蒙德追谁、Cogfly 用法、每波站位）由数据和你的手打录像补。
- 收割者跳起来往上打（你的经验，同日）：跳起上砍只打到正上方和后上方，跳起平砍能打到前上方，多数情况平砍更好。游戏数据吻合（knowledge/1.0.30000/attacks/reaper.json，主角坐标、+x 为朝向）：平砍多边形 x −0.25..3.60、y −0.42..2.69（从前下扫到头顶前方）；上砍 x −2.12..0.81、y −0.63..3.77（正上和身后）。规划器按真实多边形算命中，R3 把收割者形状接进规划器后会自动选平砍；验收里加一条：前上方目标的命中预测与实测一致。
