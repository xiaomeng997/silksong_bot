## 0. 一页摘要

**要解决的问题。** Bell Beast 的打法是"每帧一个 0.8 s 视野的字典序规划器 + 一层很薄的模式规则"，门槛已过（oracle 98.6 %、模拟视觉 94.4 %、0 WOULD_DIE）。Forum 不一样：14 波、9 类敌人、按帧算 **75 % 的时间场上有 ≥ 2 个敌人、43 % 有 ≥ 3 个、最多 8 个**（两只 Maestro + 6 只小机械，本次测量，附录 A）；还有助战、波次、刷怪点、口袋。你在 §3.5.7 指出的几件事——被夹住、怪聚在一起、怪不出招才危险、诱导长招、各个击破——都发生在 2–4 s 的尺度上，并且是**离散的选择**（打谁、站哪、等谁出招、什么时候回血），每帧的 0.8 s 贪心看不见也不该每帧重新决定。

**做法：两层。**
- **战术层（新，慢）**：每 0.2 s（外加事件触发）从一个紧凑的抽象状态出发，在 2–4 s 视野内给出一个**目标（Goal）**：打谁（ENGAGE / FOCUS）、站哪（POSITION / PRE_WAVE / POCKET）、诱谁出长招（BAIT）、怎么拆开（SPLIT）、在哪回血（HEAL）、放不放 Cogfly。它用的是**同一套**行为表、模板和运动学，只是粗栅格、按段近似，不出任何按键。
- **快层（现有规划器，60 Hz）**：照旧每帧推演、照旧按 `not Hz > not U > S = 0 > V > min P > max J` 选。目标只能进入它的 **J（打分）**、**站位与终点价值**、**候选集合的组成**（永远保留一套核心躲避候选）和**自适应视野**；**不能碰 Hz / U / S / V**。所以战术层错了、晚了、崩了，最坏是打得差，不会变得不安全；崩了就退回本地默认目标（今天 `tactics/modes.py` 的推广）。

**两层怎么保持一致**（§7）：同一模型（粗栅格由同一套支撑模板按格膨胀得到，粗"空"必然推出细"空"，有属性测试）；目标带有效条件和寿命，快层每帧检查，失效就退回默认并要求战术层立即重算；快层向上报告"目标被安全挡住"的帧数，战术层把这个目标禁忌 1 s；目标切换有滞回成本（也是按键经济）。

**算力**（§11）。现状本次实测（Bell Beast oracle 录像开环重放、4 线程、整机约 80 % 负载、低优先级）：整 tick p50 7.0 / p99 19.6 ms，其中规划器 6.5 / 16.9（推演 3.1 / 4.7，支撑 + 命中重推 + 锁定检查 2.2 / 10.4），预测 0.10 / 0.49，战术 0.26 / 3.5。Forum 的运动学每次推演贵 2.4 倍（512 × 48 bounds_lo：Forum 10.9 / 16.9 ms，Hunter 4.5 / 6.1 ms），直接移植规划器会在推演一项上就超过一帧。分层让快层**少做事**：目标已经定了打谁、往哪去，快层候选从 357+ 降到约 160–192（192 × 48 bounds_lo 实测 4.6 / 6.9 ms），超视野的尾巴检查大部分由战术层的逃生价值栅格代替。战术层的粗栅格成本按本次代理测量（Bell Beast 预测上 1 u 栅格 × 20 个时间格到 4 s：占用 p50 0.24 / p99 3.3 ms，概率 0.19 / 5.3 ms，预测 4 s 0.06 / 0.65 ms）推算，每个战术 tick 约 3–15 ms，按确定性的分片摊到 12 帧里，每帧 ≤ 1.5 ms。M2 Forum 门槛期的目标：**每场 tick p99 的中位数 ≤ 14 ms**（不比 Bell Beast 过门槛时差），迟到帧不多于 Bell Beast；3–4 ms 留作 M3 之后的目标（§11.4 给出路线）。

**先做什么**（§15）：F0 先把 Forum 支撑做成保守的（现有 13 场的留出核对九类都没到 ≈ 0，而之后又录了约 115 场完整连战，先用全部约 128 场重建）→ F1 多敌人预测 → F2 快层 Forum 词汇（冲刺、墙、Reaper 判定）和接口（先用固定默认目标）→ F3 不带战术层的基线实战 A0 → F4 战术层 v1（选目标、站位、口袋、回血点、波前站位）→ F5 机会 / 诱导 / Cogfly、权重拟合 → F6 冲刺斩 / 飞针运动学 → F7 拼刀整场 A/B → F8 门槛（≥ 200 场完整连战，CLEAR ≥ 70 %，WOULD_DIE ≤ 1 %）→ K1。每步有验收测试。开发期用**按波的 savestate** 做 A/B（DESIGN §3.9.3：阶段存档只用于练习，不计门槛），门槛只用完整连战。

## 2. 为什么分两层（而不是把规划器做大）

1. **决策的尺度不同。** "先打哪只""站到哪一侧把两只拆开""等 Clapper 跳起来再砍""这一波结束前站到哪"是 1–4 s 才兑现的离散选择；"这一帧按不按跳"是 16 ms 的连续选择。把前者塞进逐帧的候选搜索，候选数按"目标 × 动作"相乘，视野还得拉到 2–4 s（远期支撑变宽，几乎所有长计划都不安全，见 M2.md"超过视野的长招"）。
2. **算力上只能这样。** 规划器的成本 ≈ 候选数 × 视野 × 时序分支 × 每步代价（Forum 2.4 倍）+ 支撑查询 ≈ 候选 × 视野 × 在场放置数。把视野从 0.8 s 拉到 3 s、候选翻倍，成本涨约 8 倍；而战术层在粗栅格上一次算完所有目标，0.2 s 才算一次。
3. **逐帧重选会抖。** 现有规划器靠"保持上一计划"的加分和宏承诺压住抖动（M2：2,433 个下劈宏在按下前都被换掉）。多敌人时目标之间价值接近，逐帧重选会在两个目标之间来回切（违反你的按键经济标准）。慢层 + 滞回天然解决。
4. **安全不需要上移。** 你的要求是钢魂下"支撑安全"不打折扣。分层后安全仍完全在快层每帧检查；战术层只负责"把主角带到好局面"，你说的"站位价值、诱导、各个击破"本来就只影响打分（§3.5.7 第 2、5 点："诱导只影响打分，不影响安全"）。
5. **和 DESIGN 的层次一致。** §3.5.1 本来就有 L3 剧本（每场）/ L2 战术（10 Hz + 事件）/ L1 规划器（60 Hz）。Bell Beast 的 L2 只是一个每帧调用的规则表；本方案把 L2 做成真正的慢层，L3 剧本给它波次知识。

不选的方案：扁平大规划器（算力不够，见上）；学习型战术选择器（§3.5.8 移到 §3.11，且样本太贵：一场 14 min）。

## 4. 多敌人预测与支撑组合（两层共用）

### 4.1 结构

- **每个在场敌人一个 `EnemyTracker`**（`BossTracker` 的推广：状态、进入时刻、锚点、朝向、HP 估计），按 iid 建立、按死亡删除；同类共用一个 `BossModel`（behaviour + 模板）。按 iid 分流的做法与 `gauntlet_tables` 建表时一致（事件按 `ent`、接触按来源路径）。
- **敌人放出的危险物**（Bellbearer 的钟、Reed 的针、Clawmaiden 的矛和矛爆炸、Clapper 的 rune bomb / rune slam）在运行时按建表时的规则归属（放它的那招、4 s 窗口）；能精确推算路径的（钟的弹跳与被打改向，Bell Beast 的 `bell_track` / `pogo_targets` 的规则，Bellbearer 的 `Throwing Bell` FSM 同样有 Tink → 改向）走精确路径分支，其余用 self 模板。
- **波次与入场**：`WaveSchedule` 用公开规则（`BattleScene`：本波敌人数降到 `remainingEnemyToEnd` → 下一波；开波 1 s 后数一次子物体；`startDelay`）和**看到的击杀**推下一波的开始时刻区间，把下一波敌人的 `*_ENTRY` 支撑按刷怪点放进去（Clapper 的 Drop In 从 (21.03 / 42.03, 23.7) 落下；Clawmaiden 从 (1.67, 46.23) 飞进来）。oracle 的 `room.battles` 只给测试框架用，不给预测器（§12）。
- **垂死身体**：被打死那一帧之后，最后的身体框再保留若干帧（Clapper 终局约 13 帧，按建表的"死亡帧接触"统计定），这是 13 场里 5 次样本内失败的来源。
- **助战**：Garmond、Cogfly 不是威胁（攻击只打敌人，§3.5.7）。但他们会把敌人打退、打出硬直，这些都在有助战的录像里（行为表是在 fo_A 助战组上建的）；**后备组（无助战，fo_C）要单独核对留出召回**，否则支撑里缺"没人打它时的走位"。

### 4.2 支撑的组合

- **支撑 = 各敌人支撑的并集。** 理由：每个敌人的支撑是"它所有可能的下一步"的并集（行为表的全部观测分支 + 状态机结构上可能的分支），本来就是在多敌人、有助战的录像上统计的，不以别的敌人怎么动为条件。所以并集覆盖联合的所有可能。会破坏这一点的是**敌人之间的耦合**没进数据：Clapper 的 `AVOID BUDDY`（两只互相让）、Maestro 召唤、Garmond 打断。前两者在数据里（终局 39 只 Clapper、117 只 Tiny）；防线是留出召回（F1 验收）。
- **D1（监督器）= 在支撑内的敌人里最大的单次事件**：Clapper、Clawmaiden 矛在支撑内时 D1 = 2，否则 1。多段攻击（Choristor 鞭、Reed ParrySlash、Minister Slash）按 Q3 的现行定义应记为 `hits > 1` 的事件（Forum 的 SupportEvent 还没实现，F1 定），**于是在 h = 2 时触发 Q3（退出）**。不同敌人的命中不叠加：受击后 1.2 s 无敌挡住其他敌人（危险物除外，Forum 场内没有危险物）。这一条进入战术层的"h 暴露"价值（§5.6）。
- **概率（只用于打分）**：`P(contact) = 1 − Π_i (1 − p_i)`（敌人之间独立的近似）；每只的 p_i 照旧来自行为表的平滑转移概率，条件变量按检验保留（距离、朝向、出招历史）。
- **不保守的支撑怎么用**（现状九类都不过）：F0 先用全部约 128 场完整连战重建、按场分折核对；仍超出的类型，规划器读到 `support_ok = False` 时按该类留出残差的 p99.9 加膨胀余量（每类、每家族），并把这些类的"首次出现 n < 30 的分支"按最坏情况（§3.5.8）。F1 的验收是留出召回 100 %（与 Bell Beast 的 23,896 / 23,896 同一口径）。

### 4.3 成本

- 支撑查询的成本 ∝ 候选 × 帧 × **在主角附近的放置数**：`fastquery` 已经按（放置，步）跳过包围盒碰不到候选的组合（"场地另一侧的攻击铃不花钱"）。Bell Beast 每 tick 20–60 个放置；Forum 按 1.2 的在场数（p50 2–4、Maestro 波 8）估计 30–120 个放置，其中 6 u 内的敌人：p50 0–1 只、≥ 2 只的帧 0–29 %（表 1.2）。
- **小机械成群**（最多 6 只、95 % 的帧挤在 3 u 内）：同类、同阶段、位置接近的几只合成一个"群模板放置"（各只模板并集的外框按位置平移），超过 3 只时启用；精确性只损失在群内部（合并只会变大，保守）。
- 预测本身（树的展开）按敌人线性：Bell Beast forecast(2 s) p99 0.49 ms，4 s 0.65 ms；Forum 每只敌人的状态图更小（大部分家族 1–3 个状态），估计 8 只时 p99 ≤ 3 ms，F1 实测。
- 战术层与快层**共用同一次预测**：每帧 `update` 一次；快层用 0.8–2 s 的放置，战术层在它的 tick 上要 4 s（一次额外的 `forecast(4.0)`）。

## 5. 战术层

### 5.1 抽象状态

见 §3.3。要点：
- **敌人相位只分四类**：ENTRY（入场，支撑由刷怪点和入场模板给）、IDLE（在决策链里，支撑 = 它所有可能的下一招）、COMMITTED（在一招里，支撑收窄到这招剩下的部分 + 之后的决策）、DYING。COMMITTED 带 `t_free`（这招最早 / 最晚结束）和 `windows`（这招里主角"出刀 + 后摇"放得下的空档：在模板上对"贴近该敌人可打框的位置"逐时间格检查，长度 ≥ 出刀生效 + Reaper 硬直 0.3 s + 余量）。这正是你说的"出招有破绽，不出招才危险"的可计算形式。
- **`t_strike`**：从现在起它最快能打到主角当前位置的时刻，在支撑上算（待机时 = 该类型"从待机到最快一击"的时间和距离；承诺中 = 本招剩余部分与之后决策的最早接触）。每类的"待机 → 最快一击"从行为表统计（F0 的数据产品：从决策状态进入到攻击判定第一次伸出待机身体外框的时间分布，按距离档）。
- **粗栅格**：x 14–49、y 3–17，1 u（约 35 × 14 = 490 格），时间格 0.2 s 到 4 s（20 格）；每个敌人一层支撑位图（用快层同一套模板，按格对角线的一半额外膨胀：格子被标"空" ⇒ 格内任何主角受伤盒中心的细查询都"空"，§7.1）和一层概率。
- **主角可达时间表** `R(Δx, Δy | contact, vx 档, 面向)`：离线用 Forum 运动学（nominal 车道）对宏原语（跑、跳 4 档、冲刺、冲刺接跳、蹬墙跳、爬墙、松墙下落、滑翔）做广度优先展开，记录到达每个相对格的最短时间；运行时查表，不做推演。只用于打分，不承担安全（安全由快层逐帧检查）。

### 5.2 目标种类

| 目标 | 含义 | 产生条件 | 给快层的东西 |
|---|---|---|---|
| ENGAGE(i, side) | 打 i，在它的惩罚窗口里出刀 | i 有 `windows` 或 i 可打且其它敌人的 `t_strike` 足够晚 | 区域 = i 可打框旁 side 侧的出刀带；`hit_w[i] = 1`；视野延到 i 这招结束 |
| FOCUS(i) | 各个击破：集中打 i 到死 | 其它每只 j 在 T_focus 内都够不到（`t_strike_j` ≥ min(TTK_i, 1.5 s)，或锁在长招里） | 同 ENGAGE，`hit_w` 其它 0.2；击杀加分 |
| BAIT(i, 距离带) | 站在让 i 出"长、原地、可惩罚"招概率最高的距离带 | 行为表对 i 的选择依赖距离（Clapper 的 Slam Range、Choristor、Minister、Reed、Bellbearer、Tiny） | 区域 = 距离带；`hit_w` 低；视野不延 |

### 5.3 价值（超视野的站位、间距、机会、击杀）

对每个目标 g，在抽象状态上估计（全部是打分，不是约束）：

```
V(g) = w_E·E(g) + w_O·O(g) + w_K·K(g) − w_R·R(g) − w_T·T(g) − w_H·H(g) − w_S·Sw(g) + w_W·W(g)
```

- **E 逃生空间**（你的第 1 点）：主角在目标区域、到达时刻 t_a 时，接下来 1–2 s 内能到达且到达时空着的格子的加权面积：`E(c, t_a) = Σ_{c'} κ(R(c→c'))·free(c', t_a + R(c→c'), +δ)`，κ 随到达时间递减。被夹住、退到死角、站在下一波刷怪点上，E 都自动变小；墙角不硬编码（Forum 的左墙顶口袋是"空着"的格子，E 自然高）。实现：先算每格的"空闲时段"，再用预先算好的可达模板（每个 contact 类一份，约 200 个相对格）做稀疏卷积；490 格 × 200 × 5 个时间格约 50 万次运算，numba 约 0.5 ms【估计】。
- **间距与危险区重叠**（你的纠正：判据是"危险时段和危险区是否重叠、是否留出能安全出刀的空档"，不是左右）：`slots(g)` = 在目标区域附近、未来 2 s 内能放下"出刀 + 后摇"的（格，时间）数，按敌人分开再合并；两只的危险区叠在一起时 slots 变小。E 和 O 已经隐含它，单独列出是为了审计和权重拟合。
- **O 机会价值**（你的第 4、5 点）：`O(g) = Σ_i hit_w_i · Σ_m P_i(m | 主角在区域, 距离, 高度, i 的出招历史) · win_i(m)`，m 是 i 的下一招，`win_i(m)` 是这一招给的安全输出时间（从模板的 `windows`）。待机的敌人按"最快可能的出招"核验先手（主角"出刀 + 后摇"短于它待机到打中的时间且在其判定外）；已承诺的敌人直接用剩余窗口。两只的组合（"A 放长招时去打 B"）：对承诺中的 i 和另一只 j 评估复合目标 ALTERNATE(j → i)：先 ENGAGE j 到 `t_free_i − 余量`，再转向 i 的惩罚窗口；只对价值前 6 的目标做两步组合（≤ 30 对）。
- **K 击杀**（各个击破）：`K = Σ_i hit_w_i · DPS_i(g) / hp_est_i · Θ_i`，Θ_i = i 让危险区变大的量（它的支撑覆盖面积 × 剩余时间，和"打铃改向"同一原则：击杀永久移除一份威胁）。DPS_i 按类型实测（Reaper 钉子 9 / 下，助战 Garmond 5 / 下按他当前目标计入）。Clawmaiden 偷丝，剧本给额外权重（DESIGN：先杀偷丝者）。
- **R 风险概率**：`P(2 s 内挨打 | 特征)` 的逻辑回归（特征：各敌人距离按类型、相位类、主角在房间里的位置、离墙 / 刷怪点、两侧有敌、重叠量），从采集数据和实战拟合（§3.5.7 第 2 点）。只进打分。
- **T 路程**：`R(当前 → 区域)`。
- **H h 暴露**（本方案新加，来自监督器的耦合，§5.6）：未来 1 s 内主角所在区域被 2 格伤害源（Clapper、Clawmaiden 矛）或多段攻击源（Choristor 鞭、Reed、Minister）的支撑覆盖的比例，按当前 h 加权（h 越低越重）。它让战术层在 h = 2 时远离会触发 Q3 的敌人，去打别的敌人攒丝。
- **Sw 切换成本**：换目标付 Δ（滞回）；也是按键经济。
- **W 波次项**：剧本的先杀顺序、波前站位与刷怪点的关系（不站在 Clapper 的 Drop In 落点和 Clawmaiden 的入场路径上；站在能先接一只、另一只要走一会儿的一侧）。

权重先手设（每项一个物理含义的单位：秒 × 面积、秒、命中数），再在按波的 savestate 批次上用 CMA-ES / 贝叶斯优化拟合（§3.5.8 允许：只影响性能）。

### 5.4 搜索与滞回

- 枚举：敌人 ≤ 8 × {ENGAGE 两侧、FOCUS、BAIT 两个距离带} + POSITION 锚点（地面每 3 u 一个，约 12 个，加口袋）+ PRE_WAVE 候选 + HEAL（有资格时）+ COGFLY + LOCAL：一般 30–60 个；两步组合 ≤ 30 个。
- 过滤（不是安全，只是去掉明显不可行的）：目标区域在到达时刻被支撑覆盖（粗栅格）→ 降为不可行；HEAL 只在 `heal_first`；POCKET 只在终局剧本允许且口袋规则成立。
- 选择：`argmax V`；在任的目标加 Δ（默认 0.15 × 当前最好值）；被快层报告"挡住"的目标禁忌 1 s；事件触发的重算不加 Δ（局面变了）。
- 成本：特征都是查表和小数组运算，一次 ≤ 1 ms【估计】，主要成本在粗栅格（§5.5）。

### 5.5 调度：什么时候跑、跑在哪、怎么保证可重放

- **周期 0.2 s（12 帧）+ 事件**：敌人 IDLE ↔ COMMITTED 切换（可观测相位）、敌人死亡 / 入场、开波、新危险物、主角受击、风险档变化、PAUSE_PENDING、FORCED_RISK、目标失效或被挡、Garmond 进场。事件触发的重算之间至少隔 6 帧。
- **在规划器同一线程里分片执行**，固定的确定性计划（不用墙钟决定做多少，所以离线重放与实战一致，`view_compare` / `postmortem` 能复现）：帧 0 构造抽象状态 + `forecast(4.0)`；帧 1..E 每帧一只敌人的粗栅格（占用 + 概率）；下一帧逃生价值栅格；下一帧目标枚举与价值；结果在第 k 帧生效。事件触发时整个流水线重启（旧目标在新目标出来前继续有效，除非失效）。
- 每片的成本按 §1.3 的代理测量：一只敌人的 1 u × 20 格占用 p99 约 3.3 ms、概率只算到 2 s（10 格，p99 2.3 ms）；逃生价值约 0.5 ms；目标约 1 ms。**每帧附加 ≤ 1.5 ms（p50）、≤ 4 ms（p99）**【估计，F4 用 `tactical_bench` 实测】。
- 为什么不放到别的线程：Python 的 GIL，现有 numba 核没有 `nogil`；分片在同一线程里既确定又简单。最终运行（一个游戏实例、24 个空闲逻辑核）可以把栅格核改成 `nogil` 放到 E 核线程，F4 之后再看需要。

### 5.6 与监督器的关系

- **Q1a 回血**：监督器给 `heal_first`，战术层选 HEAL 的地点：原地（快层推演里 Bind 提交测试通过）、地面安全点、或口袋（需要先实测"贴墙时能不能 Bind、Bind 会不会脱墙"【未核实】，在此之前口袋不当回血点）。去回血点的每一步照旧由快层的支撑检查保护。
- **Q6（h = 2 时攒丝）**：`heal_first` 且丝 < 9 时，战术层在 K 里给"普通攻击命中"加权（剧本 `bind.gather_hit_x`），并加大 H：去打不会触发 Q3 的敌人（单段攻击的 Bellbearer、Maestro、Tiny），离开多段攻击的 Choristor / Reed / Minister 和 2 格伤害源。
- **Q3**：h = 2 时只要支撑（0.8 s）里有多段攻击就退出。所以 H 项是"保持支撑温和"：对整场的退出率影响很大（Forum 里多段攻击的敌人在第 0、1、2–4、8、9、11、12 波都有）。
- **YELLOW**：目标的 `max_hits` = 1；不选新的 ENGAGE 去碰多段攻击；不弹反（PAUSE_PENDING 同）。
- **PAUSE_PENDING**：战术层冻结，目标 = LOCAL（只躲）；快层本来就禁止攻击。
- **最后一击（I3）**：Forum 最后一个敌人死时有 1.85 s 的 `EnemyBattleEndSlow`（不可暂停），I3 要求"满血、面具完好、窗口内最坏事件之后 h ≥ 2"才能进入。所以终局最后一只 Clapper 的 `hp_est` 低到一两刀能死时，战术层先排 HEAL（满血），再 ENGAGE；U 的"可能致死的一击"在 Bell Beast 指打死 Boss 的那一刀（Boss 死亡的 1.35 s 慢动作是 I3）；Forum 的普通敌人 `bigEnemyDeath = 0`，只有本场最后一个波次成员的死亡触发 1.85 s 慢动作，所以 U 移植为"可能打死本场最后一个波次成员的一刀"（Clapper 自己有没有死亡慢动作【未核实】，有就同样算）。这是规则的移植，不受目标影响。**Garmond 也可能打出最后一击**，这不受我们控制：终局最后一只低血时，主角不满血就留在口袋或远离（等于让 Garmond 的那一刀发生在主角安全的时候）。这一点要实测慢动作期间敌人是否继续攻击（facts：慢动作里垂死本体照样伤人）。

## 6. 目标如何变成快层的偏好

**原则：目标只能改 J、候选集合的组成（不能去掉核心躲避集）和视野长度；Hz / U / S / V / P 的计算和字典序一个字不改。**

| GoalPrefs 字段 | 快层里的作用 | 与现有代码的对应 |
|---|---|---|
| `region` | J 的站位项：终点到区域的 2D 距离（按可达时间归一）、终点在区域内的加分；contact = wall 时要求终点处于贴墙 | 代替 `stance_x`（`_score_kernel` 的 stance 项） |
| `hit_w` | J 的命中项按敌人加权：命中预测对每个敌人的可打框（均值路径）分别算，乘 `hit_w` 再加总；击杀加分只给目标 | 现在只有一个 boss box（`f.boss_box`） |
| `esc_grid` | 终点价值：推演终点的格子在战术层逃生价值栅格上的值（2D，到达时刻取终点时刻） | 代替 1D 的 `risk_x` / `risk` |
| `vocab` | 候选集合 = 核心躲避集（永远在，约 48 个）∪ 目标相关的候选族（约 96–128 个）∪ 上一计划 ∪ Bind 宏（想 Bind 时）；总数 ≤ 192 | `candidates.build` → `build_forum(vocab)` |
| `horizon_f` | 自适应视野：目标锁在已知时长的长招里时，视野延到它结束 + 反应时间（≤ 2 s） | 现有 `horizon_frames` |
| `want_bind`、`bind_spot` | Bind 宏（提交测试仍在推演里做）；去 spot 时 `region` = spot | 现有 HEAL / HEAL_SPOT |
| `max_hits`、拼刀开关 | 照旧来自监督器和剧本（拼刀按整场 A/B 的结论按类型、按招开） | 现有 |

**核心躲避集**（与目标无关、每帧都在、都按 bounds_lo 推演）：WAIT、MOVE(L/R)、JUMP(11/24/48)×(N/L/R)、DASH(L/R)、在墙上时 WALL_HOLD / 松墙 / 蹬墙跳 / 爬墙，各配 3–4 种续段（停、跑、跳、反向）。约 48 个。它保证：**只要有不带目标的安全躲法，快层就一定能看到它**。

**为什么这样不影响安全**：S、Hz、U 对每个候选单独定义，与 J 无关；字典序先比 Hz、U、S、V，再比 P、J。目标只改变（a）同为安全时选哪个（J），（b）候选集合多了哪些（只会多，核心集不少）。所以"目标存在时 FORCED_RISK"必然推出"只用核心集也 FORCED_RISK"；反过来，没有目标时安全的核心候选在有目标时仍然在、仍然安全。V 按"同一首原语的安全兄弟 ≥ 2"算，目标族多出的兄弟只会让 V 更容易成立，核心集的兄弟永远在；U 用到的"这一刀可能打死"只看命中几何和 `hp_est`，不看 `hit_w`。属性测试见 §7.2。

**尾巴检查的变化**：现有 `_tail_pick` 在每 tick 对前 2 个安全候选的终点再推 0.8 s（停、跑、跳），检查有没有安全的后路。保留（便宜：2 × 7 条），但它不再是"超视野"的唯一信息：`esc_grid` 让终点价值本身就偏向有后路的地方，尾巴检查失败的比例应下降（`goal_audit` 统计）。

## 7. 两层一致性

### 7.1 同一模型，粗不放宽

- 两层读同一个 `MultiForecast`（同一次 `update`）、同一套行为表和模板、同一套运动学（战术层的可达时间表由运动学离线生成）。
- 粗栅格的支撑位图在放置模板时按格对角线的一半再膨胀，所以**粗格"空" ⇒ 格内任何点的细查询"空"**；反过来不要求（粗格"占"时细查询可能空：战术层只会偏保守）。属性测试：在 Forum 留出录像上随机抽 10⁵ 个（格，时间），粗空而细占的数必须为 0。
- 概率层两层都用 `1 − Π(1 − p_i)`，同一套平滑转移表。

### 7.2 目标不碰安全序

属性测试（重放 Forum 录像，每 tick 随机给 3 个目标 + 默认目标）：
1. 核心集候选的 S、Hz、U 在各个目标下逐位相同（U 不随 `hit_w` 变）；
2. 有目标时 FORCED_RISK ⇒ 默认目标下也 FORCED_RISK；
3. 只要核心集里有 S = 0 且非 Hz 非 U 的候选，选中的计划 S = 0；
4. 监督器的 allowlist 在目标的词汇之后应用（目标加的候选同样被否决）。

### 7.3 有效条件、寿命、事件（GoalArbiter，每帧）

- 每个目标带有效条件（全部是在当前 WorldState 上的便宜检查）：目标敌人还在场、还被跟踪（视觉视图：最近 0.3 s 内有检测）；FOCUS 的"其它敌人够不到"仍成立（用当前预测的 `t_strike`）；POCKET 的规则 (1)(2)（§10）；HEAL 的 `heal_first` 和丝 ≥ 9；风险档允许（YELLOW 不能有 FOCUS 多段攻击的敌人）。
- 寿命 0.6 s（3 个战术周期）；目标做出时的世界时刻 `t_made` 与当前相差 > 0.3 s 而没刷新 → 视为过期。
- 失效或过期 → 立刻用 LOCAL，并触发战术层重算（事件）。
- 区域按世界坐标、目标按 iid，所以延迟到达的目标不需要再变换；时间量（窗口、`t_free`）按 `t_made` 换算到当前。

### 7.4 被挡检测与禁忌（向上反馈）

- 快层每 tick 回报：`n_safe`、`n_safe_goal`（朝目标前进的安全候选数）、是否 FORCED_RISK、选中计划的进度。
- `n_safe_goal == 0` 且 `n_safe > 0` 连续 ≥ 12 帧 = **被挡**：目标要主角去的地方现在不安全，快层在原地躲。GoalArbiter 把这个目标标记禁忌 1 s、触发重算。这避免了"目标拉、安全推"的来回抖动。
- FORCED_RISK 发生时，战术层下一次重算把"FORCED_RISK 前 1–3 s 的局面"记进审计（`forced_audit`：离线对这段时间的每个战术 tick 重新评估所有目标，看是否存在能避免它的目标；这就是 §3.5.7 验收里的"事后审计"）。

### 7.5 滞回与按键经济

- 目标切换的滞回 Δ（§5.4）。
- 快层的"保持上一计划"加分照旧；目标不变时，上一计划在新 tick 里的 J 不会因为目标变动而跳变，计划改动率下降。
- 指标：每分钟目标切换数、计划改动率、每秒按键数（M2.md 按键经济），A/B 时与 A0 比较。

### 7.6 失败安全

- 战术层抛异常、超出分片预算、或 F4 之前根本不存在 → LOCAL。测试：开环重放里随机注入战术层失败（10 %、100 %）：每 tick 核心集的 S / Hz / U 与无战术层时逐位相同；100 % 注入时整个决策（选中的计划、FORCED_RISK、监督器触发）逐位相同。
- 战术层只读 WorldState 和 MultiForecast，不读原始 STATE（§12），在 degraded_dust 视图下同样运行。

### 8.2 候选预算

- 每 tick：核心集约 48 + 目标相关约 96–128 + 上一计划 + Bind 宏 + 下劈细网格 ≤ 16，总数 ≤ 192。全部按 bounds_lo 推演（实测 192 × 48：p50 4.56 / p99 6.86 ms，§1.3）。

- **命中效果重推只做 J 最高的 24 个**（现在对所有命中候选重推，是支撑一项 p99 的大头：hit_fx 0.19 / 7.62 ms）。
- **两段推演（备选）**：nominal 推全部、bounds_lo 只推 nominal 安全且 J 前 K 的加核心集；最终只在 bounds_lo 验证过的候选里选，验证过的都不安全时再推下一批，直到全部或预算用完（预算用完才宣告 FORCED_RISK，并单独计数"预算型 FORCED_RISK"）。实测在 192 的规模上收益不大（nominal 192 + bounds_lo 64：p99 约 2.6 + 3.3 ms，对比直接 bounds_lo 192 的 6.9 ms），所以先不做，候选数要 > 300 时再用。

### 8.3 多目标打分

- 命中预测按敌人分别做（每只的可打框沿其均值路径，现有 `_attacks_of` 的循环对 E 只敌人重复；E 一般 ≤ 4，小机械群按群框）。
- 被打死那一帧之后的身体照算（§4.1），命中加分在 `hp_est` 降到 0 之后停止。
- YELLOW 的"不打可能致死的一击"（击杀冻结会吞暂停）照旧对每个敌人生效：要每只敌人的 `hp_est`（视觉视图只数看到的命中，偏高，所以这条偏严）。本场最后一个波次成员的那一刀另外按 I3 进 U（§5.6）。

### 8.4 拼刀（降低风险的动作）

- **哪些能拼**（facts §9.2 的 parry 位 5）：Clawmaiden 的 Slash Collider 1–4、Minister 的 ParrySlash Hit 1–4、Maestro 的 Slash Hit 1/2、Reed 的 Stab Hit 1–3 和**飞针 Pin（可弹开）**、Envoy 的 Charge / P1 / P2 / JumpSlash Damager、Choristor 的 Slash / Spin / Spin Slash；Clapper 全部和 Clawmaiden 的矛只有反击位（4），不能拼。Bellbearer 的钟可以被钉子打改向（Tink，同 Bell Beast 的铃）。
- **推演模型**：攻击多边形的生效帧与可拼刀的伤害框重叠 → 两个分支：成功（p_succ）：该敌人这一招的余下模板从支撑里撤掉、主角 0.15 s 拼刀无敌、攻击冷却和后摇清零（M2.md 反编译结论）、拼刀冻结（世界停，暂停被吞：YELLOW 与 PAUSE_PENDING 禁用）；失败：照常。
- **风险**：成功分支安全、失败分支不安全的拼刀方案 S = 1，只在 FORCED_RISK 时与别的方案按 P 比（P = (1 − p_succ) × 失败分支的接触概率）；两个分支都安全的拼刀按 J 正常比（收益：弹开飞针 = 威胁消失，取消后摇 = 立刻反击）。
- **成功率**：按（类型，招，视图）实测：效果挖掘 + 定点实验（M2.md 机制发现流程），oracle 视图的成功率主要取决于出招时机预测；视觉视图另测。
- **用不用**：整场 A/B（拼刀开 / 关，按类型、按招），比每场受击、WOULD_DIE 上界、退出数、用时（§3.5.6 修订）。战术层只在 O 里反映：开了拼刀的敌人，近身的"安全窗口"更多。
- **一致性检查**（M2.md"效果已知的动作不能让危险区变大"）：对每次拼刀（录像 + 模拟），拼刀方案在主角周围 1 s 内的危险区不得大于不拼的方案；违反就是模型错误。

## 10. 末波：左墙顶口袋

- **它是 POCKET 目标 + 剧本规则 + 快层的普通安全检查**，不是特殊模式。
- **进入**（规则 1，facts §10.4）：回口袋前没有 Clapper 贴在左墙边（本体左沿 ≤ 14.6）。这是 POCKET 目标的有效条件；不成立时目标变成 POSITION（远处等）。
- **在口袋里**（规则 2）：任何面朝左、pos ≤ 18 的 Clapper 都按威胁算——它这时起跳，本体会擦到口袋 1 u 以内或进入。这不需要额外代码：快层的支撑检查在 CC_JUMP / CC_JUMP_CAST 的模板按起跳点锚定时自动覆盖（前提是支撑覆盖了少见的近墙起跳，F0 留出核对）；战术层把这种局面的逃生价值算低，准备下墙。
- **出刀**：Clapper 跳到最高点时墙砍。快层的 J 对 Clapper 在 Air 阶段的可打框（均值路径）按 Reaper 墙砍多边形算命中；够距按录像的下界 4.0–4.3 u，真正的最远距离要实测（F2 的数据项）；所以"在最高点砍一下"对较近的一半跳可行。
- **下来打**：战术层在两只 Clapper 都不在 Slam Range 内能威胁地面某段、或一只锁在长招（CC_CAST 1.25 s、CC_JUMP_CAST 2.2 s）、另一只远或被 Garmond 缠住时，给 ENGAGE；快层验证安全。你的"地面安全时下去打"就是这个价值比较。
- **爬上去**：CLIMB_POCKET 宏（数据策略的口袋模式里爬上去的少：贴墙 5,621 帧里 145 帧在 y ≥ 13.3），先用运动学离线找出从地面到 y 13.45–13.60 贴墙的按键序列（蹬墙跳 + 爬墙），再做成宏；每帧照常检查安全。
- **回血**：口袋作回血点要先实测贴墙 Bind（能不能、会不会脱墙、Bind 期间受伤盒）。
- **最后一击**：§5.6。
- **余量**：口袋离各招 ≥ 2.0 u，但 Clapper 的留出核对 0.4 % 超出 0.5 u；口袋点的覆盖图核验要用 F0 重建后的表重跑（`coverage_map` 保守栅格），`SafeSpot.verified` 填运行与代码。

## 11. 计算预算

### 11.1 帧预算

一帧 16.7 ms。快层（含预测 update、GoalArbiter、规划器）+ 战术层分片 + 胶水（WorldState、HoldFilter、监督器）必须在这一帧里出结果，否则迟到、跳帧（Bell Beast 视觉视图的迟到帧 p50 7 / 场）。

### 11.2 估计（训练负载下，4 线程）

| 组件 | Bell Beast 实测 p50 / p99 ms | Forum 估计 p50 / p99 ms | 依据 |
|---|---|---|---|
| 预测 update + forecast(2 s) | 0.10 / 0.49 | 0.3 / 2.0 | 按在场 2–4（最多 8）只线性；小机械合群 |
| 推演（候选 192 × 48，bounds_lo） | 3.05 / 4.69（357+，Hunter） | 4.6 / 6.9 | §1.3 实测 |

### 11.3 战术层自身

- 每个战术 tick：预测 4 s 0.06 / 0.65 ms（实测）；每只敌人粗栅格占用 p99 ≈ 3.3 ms、概率（2 s）p99 ≈ 2.3 ms（Bell Beast 代理实测，Forum 每只敌人的放置比 Bell Beast 少，栅格格数多 1.4 倍）；逃生价值约 0.5 ms【估计】；目标约 1 ms【估计】。4 只敌人约 8–25 ms，摊到 12 帧。
- 若事件过密（例如 Maestro 波小机械反复入场），事件触发的重算最多每 6 帧一次，超出的事件合并。

### 11.4 之后怎么到 3–4 ms（不阻塞 M2）

1. 推演与支撑查询融合成一个 numba 核（不物化 [N, T, 4] 的包络，边推边查，碰到接触就停这条）：省去大部分支撑查询和内存流量。
2. 最终运行只有一个游戏实例：快层可用 8 个 P 核线程（训练时 4 个实例共享），推演约减半。
3. 核心集与目标族按局面再剪（空中时不需要地面起步族等）。
4. 战术层改 `nogil` 放 E 核线程。

- 开发期 A/B 在按波 savestate 上做（每波 ≥ 100 次 / 组）；门槛只用完整连战。

### 14.2 指标

- 结果：CLEAR、QUIT（按触发器：Q1 / Q1a 失败 / Q3 / Q4 / Q6）、WOULD_DIE（含"最后一击之后"的 4.1 s）、STUCK、用时（每波、整场）。

- 打法：**敌人处在承诺招里的时间占比**和"主角命中里落在敌人承诺招里的比例"、**每秒输出**（按敌人类型）、击杀来源（Hornet / Garmond / Cogfly）、Clawmaiden 偷丝次数。

- 按键经济：每秒按键数、计划改动率、按键提前量分布（与你的录像比）。
- 事后审计：每次 FORCED_RISK 往前 1–3 s 的反事实（`forced_audit`）；每次受击的 postmortem。

### 14.3 门槛

- M2 Forum：完整连战（oracle 视图）≥ 200 场有效，CLEAR ≥ 70 %、WOULD_DIE ≤ 1 %（按 §3.9.4 的 Beta 后验报区间）；然后一小批 degraded_dust 作纪律回归。

- 吞吐：一个实例一小时约 4 场（若规划器打得比数据策略快会更多），200 场约 50 实例小时，4 实例约 12.5 h。

## 16. 主要风险与对策

| 风险 | 后果 | 对策 |
|---|---|---|
| **快层超时**（Forum 运动学 2.4 倍、多敌人放置） | 迟到、跳帧，Bell Beast 上已见过因此受击（m2_vision_view §8a） | 目标约束候选（≤ 192）、重推限前 K、战术层分片；F2 / F4 的延迟验收；不够时上两段推演或降 T 到 40（需重测舒适度检查的效果） |
| **支撑不保守**（九类留出都未过） | WOULD_DIE 的直接来源 | F0 先做，F1 的召回 100 % 是硬门槛；余量按类按家族；Envoy 等 n < 30 的分支按最坏 |
| **两层打架**（目标拉、安全推，来回抖） | 按键浪费、站位反复、被夹 | 被挡检测 + 禁忌、滞回、粗栅格只会更保守、快层向上反馈；`goal_audit` 指标 |
| **战术价值设错** | 比 A0 还差 | 消融、按波 A/B、权重拟合；LOCAL 后备随时可用；A0 一直是对照 |
| **Q3 退出过多**（多段攻击的敌人到处都有，h = 2 就退） | CLEAR 率被退出吃掉 | H 项（h = 2 时远离多段攻击源、去打单段的攒丝）；HEAL 优先；按触发器统计 QUIT，必要时请你复核 Q3 在 Forum 的适用 |
| **最后一击的 I3**（满血要求，Garmond 可能抢最后一刀） | 终局卡住或违反 I3 | §5.6：终局先回满血再打；Garmond 将要击杀时主角留在口袋 / 远处；实测慢动作期间的威胁 |
| **口袋的漏洞**（贴墙起跳，最近 0.87 u）和"贴墙 Bind"未知 | 口袋里挨打；回血点不可用 | 规则 (1)(2) 作有效条件；支撑按起跳点锚定；贴墙 Bind 定点实验；在此之前口袋不当回血点 |
| **冲刺斩 / 飞针建模量大** | 你说的"正常走打不到"得不到解决 | 先用冲刺接普通攻击（已建模）；F6 不阻塞门槛；数据先采 |
| **助战耦合**（后备组没有 Garmond，表是在助战组上建的） | 后备组支撑不全 | 后备组 20 场单独核对；不过就为后备组单建表 |
| **小机械成群**（最多 6 只） | 放置数暴涨 | 合群放置；Cogfly 和丝技能清群的 A/B |
| **吞吐**（一场 14 min） | A/B 太慢 | 按波 savestate；成对种子；4 实例 |
| **视觉合法性泄漏**（战术层顺手读了 oracle 字段） | 最终路径失效 | 只读 WorldState；滤镜测试扩到 Forum；degraded_dust 回归批 |
| **GIL / 确定性** | 重放与实战不一致，审计失效 | 同线程分片、固定计划；`nogil` 线程推迟到最终运行优化 |
