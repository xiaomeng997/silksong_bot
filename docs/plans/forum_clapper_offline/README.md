## 分叉的定义与证据限度

- `k = STATE.f − fa`。比较的是同一 STATE 上保存的最终输出 `mask`；发令 f 的目标是 f+2，不能直接与录像同帧 `act.mask` 比。
- `D全`：同一整局 h2 与 h2sw 回放的首次输出差异；`D局`：只从本次 fa 起找的首次差异。后者是诊断定位，不是重新认证有效前缀。回放并未在每次 fa 重置控制器。
- D 当帧单列“边界”；之前为“前”，之后为“后”。首次不同的输出可能先改变在途输入和内部状态，所以不等到身体位置分开才截断。
- 47 条有配套 h2 回放：38 条在 fa 之前已分叉，7 条首次在 k0 分叉，只有 2 条首次在 k24 分叉。另 9 条无配套 h2 回放；均能找到早于 fa 的实机输出差异见证，但不能报精确的 h2/h2sw 整局首次分叉。
- 即便两条离线回放的输出尚相同，也不证明它们会生成录像状态：实机有漏处理帧、输入延迟，SP14 原臂还不等于 h2。55/56 条在 fa 前已有 h2sw 与实机日志的输出差异见证。这里的“前”只认证已保存回放的执行路径事实，不认证反事实闭环安全或劈中。
- 原稿用 k3–4 的跳起/出钩当分叉过晚：34 条钩索案例的局部输出已在 k0 分叉（有配套 h2 的 27 条；另外 7 条由实机 k0 输出直接证实）。不要把那之前发出的不同跳键忽略。
- 另做了 HoldFilter 的理想 f+2 送达检查；它会因实机延迟与录像提前不同，不能拿它替代 D。其结果仅留在 JSON 的 `ideal_delivery_*` 字段，不参与下表重标。

## 34 次实机钩索攻击接受帧

`C`=钩索锁定后 `hero_accepting_input` 首次 false→true 的 STATE（34/34 的 atk_cd 在此为约0.15 s）；这帧仍可显示 Harpoon Catch。`C策略`=接受输入且动画不再是 Harpoon，34/34为 C+1。`P`=实际锁存 down+attack 上升沿；`S`=DownSlash/DownSlashAlt 开始且 atk_t=0；`H`=该目标的真实 Down hit 事件。C、P、S、H 都取游戏记录，不取模拟。表内绝对攻击开始帧可直接定位录像。

- 34/34：S=P，输入到攻击开始延迟0帧；随后均有目标 Down hit。P−C 分布：13×1、14×7、15×4、16×11、17×6、18×4、21×1。以 C策略为零点则全部减1。
- **C+9 / +10 / +11 的攻击尝试数各为0。** 不能从成功样本推断这些帧输入必定成功或必定失败，更不能据此把 FREE_MIN 从10改成9。
- 帧末 `can.attack` 首次为真：C+9有10条，+10有23条，+14有1条。它是帧末的通用 CanAttack 谓词，不是这帧早些时候已接受一次 down 攻击的证据。+9这10条的前一帧冷却仍为正；+10这23条在+9帧末仍为正。
- 异常条10451463：C=k30，can.attack=k44，P=S=k51，H=k54。C→S的21个渲染帧只积累约16.999个游戏帧，冷却冻结使“固定帧数”更不可靠；不是一次21帧的输入排队。
- 结论：这次离线测量回答了真实接受帧，但没有覆盖待判的9/10/11边界。保留FREE_MIN=10；后续模型按冷却、动作锁、真实dt和输入采样顺序校验，不凭这34个晚按成功案例放宽表或校验。
