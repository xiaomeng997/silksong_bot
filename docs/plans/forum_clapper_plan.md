# Forum Clapper 波：下一阶段计划

2026-10-27 起草（Opus 5.5，综合 Fable 5.1、Argon 和本人 10-26 的分析）。状态：**草案，等你拍板**（第 10 节）。
本周只写计划、不写代码；额度 10-29（周四）10:00 UTC 重置后按本计划开工，每一步开工前另写这一步的一页规格。

## 0. 一页结论

- **控制器不换**：保留旧规划器（h2 = rnjb + HERO2）的同步 tick（500 行 × 36 帧，决策 p50 约 8 ms）。新东西只能以"候选行"或"打分项"的形式进去。map2 不作为控制器。
- **现在缺三样东西**：
  1. 1–3 s 的站位判断。双 Clapper 的头号死因是被另一只的跳落 / 大符文逼死，而陷阱在跳跃那只 Jump Aim 的时刻就已经设下（SP14 查过，不是规划器 bug）。
  2. 刀口表从站位出发的出刀覆盖。在 SLAM_PLAY 自己的站位上，刀口表只劈中 25/47 次锤，脚本是 45/47。
  3. 每帧保退路。拆分实验按固定帧交权，没有哪个交权帧能既保住退路又能出刀。
- **现成但没用上的东西**：旧规划器已经有终点价值 `combat/terminal.py`（E / trapped / overlap / H_exp，可达模板看到候选终点后 1.4 s）。它 10-08 只在第 0 波（多种敌人）上用身体场测过，闭环没有收益，之后默认关（`SSBOT_FORUM_TV`），**从没在 Clapper 波上测过**。所以"站位分的逃逸项"第一件事是在 Clapper 波上复核它，而不是新写一个 V(x)。
- **顺序**：第 0 步 测量协议 → 第 1 步 两个离线差集 → 第 2 步 终点价值上 w13 → 第 3 步 刀口行内联 + 每帧保退路 + 起跳接近行 → 第 4 步 机会项、四条规则、按家族退规则 → 第 5 步（按需）递归表量化重建。

## 2. 硬约束（每一步都适用）

- 时间结构不动：旧规划器的同步 tick，单线程每 tick ≤ 8 ms。
- 不准出现提交、交接、兜底、后台 worker 发 Press。所有出刀都是同步 tick 里的普通候选行，走旧规划器同一套检查（两段检查、命中分支、escape-ready）。
- 先离线、后实机。每一步一个闸门；闸门失败就停，等你决定，不在失败上继续往上盖。
- 一次只改一处，和 h2 配对比；报告里每个数都和 h2 并排。
- 每一步开工前写一页规格：离线产出什么、每个 tick 做什么、闸门是什么。你看过再开工作流。
- 每个阶段都审计掉血原因和漏掉的计划动作（没劈的锤、没打的 Idle），包括开关之间的冲突。

- w13 每臂至少 64 局，和 h2 在两个实例上逐局交错跑。每个时段都带 h2 对照，对照合并起来用，不跨时段比较绝对水平。

## 4. 第 1 步：两个离线差集（只用现有数据，不改控制器）

### 4.1 漏锤差集（L2 的 47 次锤 + SP14 的 85 次锤）

- 对脚本劈中、刀口表漏掉的每一次（L2 约 20 次，SP14 约 33 次）归类：
  - 根本没给窗口（L2 13 次）：表里没有对应的格？她在 6–7 u，缺"前摇中先起跳、在空中进 hop_slam0 格"这类接近行？还是 hop_slam0 的精确校验太严？
  - 给了窗口但没按，或按晚了。
  - 按了但判负。
- 拿脚本实际的按键序列（起跳帧、下劈帧）去查：脚本那一刀在刀口表里本来是不是一个格（看表的召回率），还是在表外。
- 产出：每一类的数量，加上对应的修法清单（缺哪些接近行模板、哪个校验阈值、表的哪块覆盖）。**闸门**：你看过清单。

### 4.2 被困差集（SP14 的被逼局面：跳落 10、大符文 7，以及 JUMPTRAP 之后的小符文 19）

- 在每个局面之前 0.5–2 s 的每个 tick，离线跑现有的 `TerminalValue`，用两种场各跑一遍：
  - 身体场：10-08 上线的形式，启发式；
  - 支撑场：用 Clapper 的预测建场。如果旧规划器的 `MultiForecast` 对 Clapper 的支撑也饱和，就改用 map2 的 L1 模型的危险区间来建。
- 看三件事：
  1. 场是否饱和：每个时间格被覆盖的格子比例。第 0 波是 100 %。
  2. 在 Jump Aim 那一刻，`trapped` / E 是否已经把"会被关门"的站位区分出来。
  3. 那时候的候选里有没有不被困的行。有，说明终点价值能救；没有，说明要更早看出来，或者要加瞄准引导。
- 产出：一张表，列出每个局面、最早能看出被困的时刻、当时是否有不被困的可选行。**闸门**：能看出且有可选行的局面过半，才进第 2 步。否则先补第 4 步里"按她的位置枚举 Clapper 选招"的那一项。

## 5. 第 2 步：终点价值上 w13

- 用第 1 步选定的场打开 `SSBOT_FORUM_TV`：J += w_E·E − w_trap·trapped − w_ov·overlap − w_H·H_exp。规则全部照开，这一步只加不减。
- 权重先用 10-08 的默认值（4.0 / 3.0 / 1.5 / 2.0）。在第 1 步的局面上离线扫一下 w_trap，挑一档：救下的局面最多，同时出刀率掉得不多。
- 时间：10-08 测的是每 tick 0.9–1.3 ms，要装进 8 ms。装不下就先减时间格的数量。
- **闸门**：w13 每臂 64 局，交错跑，对 h2。每分钟掉血要下降，而且掉血原因审计里不能冒出新的头号原因。无伤局数只作参考。
- 如果有效，这就是站位分的第一块（逃逸项），比新写一个 V(x) 便宜得多。

## 6. 第 3 步：刀口行内联 + 每帧保退路 + 起跳接近行（先做单怪）

- 按第 1 步的差集清单补接近行。重点是 hop_slam0 的接近版：前摇中起跳、在空中进刀口格，以及她晚到 6–7 u 时的版本。
- 给旧规划器的运动学模型补上钩索。钩索类刀口现在做不成候选行，原因就在这里。补完先用实机按键验证精度，过了才用。
- 刀口行排在 8 ms 截止之前，和其他行走同一套检查。不设固定交权帧：每帧在"能出刀且能脱离的行"和"保住退路的行"之间挑，退路由 escape-ready 保证，第 2 步打开后再加上 trapped。
- 去掉后台 worker 发 Press 的那条路。
- 刀口行的排序不能挤掉旧规划器自己的侧劈。拆分实验里，下劈接近按键把每次站位的侧劈从 0.34 压到了 0.11。排序规则在规格里写明。
- **闸门**：
  1. 离线回放 L2 的 47 次锤和 SP14 的 85 次锤，劈中率接近脚本（45/47、68/85），退路检查 0 违例；
  2. 然后上 w7 实机配对：关 SLAM_PLAY + CLAWSTRIKE，对 h2。看锤劈中率和每分钟掉血，不看无伤局数。

## 7. 第 4 步：机会项、四条规则、按家族退规则

- **机会项**：在终点价值里给"能接上刀口"的终点加分。对每只 Clapper，按 L1 模型、随她的位置去枚举它的下一招（近招还是远招；跳是约 8.4 u 以外才出的远招，见 `forum_planner_plan.md`），再看从终点能不能赶上那一招的刀口格。决策帧之后的伤害取决于她的位置，所以这里要按她的位置枚举，不能对所有选择取并集，否则场又会饱和。
- **四条双怪规则**（你的原话，`forum_map_v2.md` 约 1304 行）：
  1. 站在两只之间；
  2. 在两只之间时，打离它身后那面墙更远的那只；
  3. 两只必须在同一侧时，把它们压进墙角，自己绝不被压；
  4. 两只离得远时，把焦点怪往中间赶。

  先把它们当检查用：在录下的双怪局面上看，终点价值是否偏好规则的选择。不一致说明缺机制或视野不够，到时再决定要不要写成打分项。
- **按家族退规则**，一次一族，每次都在 w13 上配对：
  1. 站位类：TWO_SPACE、TWO_FOCUS、TWO_WALLSWITCH、TWO_CORNER / V2_CORNER / JB_CORNER、TWO_PUSHMID / TWO_PMCAST；
  2. JUMPTRAP 的站位段；
  3. SLAM_PLAY / CLAWSTRIKE（第 3 步的闸门过了以后）；
  4. 双怪出刀剧本（TWO_PLAY、TWO_HANDOFF、TWO_FLIPB 等）。

  每退掉一族，结果不比 h2 差才保留。

## 8. 第 5 步（按需）：递归表量化重建

- **触发条件**，满足任一才做：
  - 第 2 / 4 步的回放显示，可达模板（按终点类别的粗模板，看终点后 0.2 / 0.5 / 0.9 / 1.4 s）在空中终点、冲刺已用、钩索这些情况下判错，而且影响到了选择；
  - 500 行 × 36 帧明显漏掉了可行的刀口或退路。
- **不为提速而做**：实机控制器不用递归表；在 map2 里包络只占一次决策的 19 %，单独重建最多快 1.2–1.3 倍。它真正的用处是 1–2 s 的快速可达查询，给站位判断用。
- **方案要点**（Fable 5.1，10-26）：
  - 键量化：竖直相位、vx 分格、格点外 vy 分档、中途状态记成"动作 + 第几步"；
  - 值带区间：内区间对格内每个成员都成立，外区间盖住所有成员；
  - 地形不进键，每帧对高度区间做切割；
  - 可达、伤害、刀口三张表共用一套键；
  - 四级离线验证：可靠性（内 ⊆ 精确 ⊆ 外，0 违例）→ 封闭性（520 局回放，热身后每次决策新节点为 0）→ 完备性损失（在 235 个情境的验收集上，取损失 ≤ 1–2 % 的最粗格宽）→ 速度（36 步带伤害切割的前推 ≤ 1–2 ms）。

## 9. 不做的事

- 不新建控制器，不做 1–2 s 深搜，不做集合式每帧控制器，不做后台异步出刀，不重写旧规划器的时间结构。
- map2 不再作为控制器。它的可复用件按需接进旧规划器：HERO2、L1 Clapper 模型、clapper_windows_v2（427 万格，11 类）、侧劈 / 上劈模型、下劈判定器。
