## 0. 一页结论

- **控制器不换**：保留旧规划器 h2（rnjb + HERO2）的同步控制循环和时间结构。新东西只能以"候选行"或"打分项"的形式进去。map2 不作为控制器。
- **现在知道的四件事**：
  1. **单怪劈锤卡在按键路径。** 在 SLAM_PLAY 自己的站位上，刀口表对脚本成功出刀的静态覆盖很高（起手帧 105/113 落在 FULL 格），但拆分方案漏掉近一半：接近行只有 `drop_slam0`、固定交权帧把窗口截掉、钩索的按键校验和表不一致、后台检查晚到 6–18 帧。拆分的 25/47 是开环数，不等于闭环劈中率；静态覆盖高也不证明新路径能执行。
  2. **双怪 w13 没有当前数据。** 手头的基线（18/64、5/64、合并 23/128）和"头号死因是 Jump Aim 陷阱"都来自 10-18 的 b2 代码；之后 JUMPTRAP 改善了远跳陷阱，小符文损血升到 19。当前 h2 在 w13 的水平和损血原因排序都要重新测。
  3. **现成的终点价值现在用不上。** h2 开着 V2，规划器拿到的是 `V2Forecast` 包装，`_terminal()` 在 `f.__dict__` 里找不到 `_fc`，直接返回空：只开 `SSBOT_FORUM_TV=1` 等于没开。而且它的 `trapped` 只看候选终点后 4 个时刻的可达落点、不查路径，身体场只外推 0.3 s、不预测跳落和大符文，不能直接当"有没有退路"的判据。
  4. **测量不够判定。** 同一份代码两个时段 18/64 和 5/64；64 局一臂对无伤率的 95 % 误差约 ±13 个百分点；现有闸门没有事先定的效果大小和非劣界限。
- **推荐顺序**（待你拍板，第 10 节）：第 0 步 测量协议 + 当前 h2 的 w13 基线 → 第 1 步的剩余部分和三个前置件（终点价值接线、审计适配层、闭环台架）→ 第 3 步 刀口行内联 → 第 2 步 终点价值 → 第 4 步 → 第 5 步（按需）。原来的"第 2 步先于第 3 步"撤回。

## 2. 硬约束（每一步都适用）

- **时间结构不动**：保留旧规划器的同步控制循环。四个量分开定门槛：控制线程（同步）、计算线程数（Numba，现为 4）、包络预算（deadline_ms）、总 tick 延迟（p50 / p99，现为 13.69 / 28.57 ms）。新东西不能让总 tick p99 变差超过事先定的界限。
- **不准出现提交、交接、兜底、后台 worker 发 Press。** 所有出刀都是同步 tick 里的普通候选行。
- **退路检查分三种结果：通过、失败、未检查。** 后两种都不算安全。检查要覆盖相关危险结束和钩索不可取消的阶段（现在只看终点后 24 帧）。
- **每个实验保存完整的有效配置（全部 `SSBOT_FORUM_*` 开关）和最终按键归属**（规划器还是哪个脚本）。分数变了不等于行为变了：脚本可以覆盖规划器选的键（`train/forum_planner_policy.py` 约 989 行）。
- **先离线、后实机。** 每一步一个闸门；闸门失败就停，等你决定，不在失败上继续往上盖。
- **一次只改一处**，同时和 h2、和上一阶段的配置配对比较。
- **每一步开工前写一页规格**：离线产出什么、每个 tick 做什么、闸门的判定标准（第 3 节）。你看过再开工作流。
- **每个阶段都审计**：掉血原因、漏掉的计划动作（没劈的锤、没打的 Idle）、开关之间的冲突，以及实际发出的按键的安全性（检查覆盖率、未检查的比例）。

## 8. 第 5 步（按需）：递归表量化重建

- **触发条件**，两条都要满足：
  - 第 2 / 4 步的回放显示，可达模板（按终点类别的粗模板，看终点后 0.2 / 0.5 / 0.9 / 1.4 s，不带剩余冲刺、钩索硬直等状态）判错到影响选择，或者候选行明显漏掉了可行的刀口或退路；
  - 较小的修复不够：给模板加状态分类、加少量候选行之后仍达不到要求。
- **不为提速而做**：实机控制器不用递归表。它真正的用处是 1–2 s 的快速可达查询，给站位判断用。
- **方案要点**（Fable 5.1，10-26）：键量化（竖直相位、vx 分格、格点外 vy 分档、中途状态记成"动作 + 第几步"）；值带区间（内区间对格内每个成员都成立，外区间盖住所有成员）；地形不进键，每帧对高度区间做切割；可达、伤害、刀口三张表共用一套键。
- **离线验证**：可靠性（内 ⊆ 精确 ⊆ 外，0 违例）→ 封闭性 → 完备性损失 → 速度。开工前写明：热身集；封闭性统计的范围（520 局回放热身后新节点为 0，只证明这个集合上的经验闭合，不证明任意实机状态）；完备性损失的分母（235 个情境的验收集）；速度看哪些分位数；内存上限。
