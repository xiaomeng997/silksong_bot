## 0. 一页结论

- **控制器不换**：保留旧规划器 h2（rnjb + HERO2）的同步控制循环和时间结构。新东西只能以"候选行"或"打分项"的形式进去。map2 不作为控制器。
- **现在知道的四件事**：
  1. **单怪劈锤的执行路径尚未验证。** 在 SLAM_PLAY 自己的站位上，刀口表对脚本成功出刀的静态覆盖很高（起手帧 105/113 落在 FULL 格），拆分方案的开环判中数低得多，但逐条重标表明多数事件已经在首次分叉之后。只允许 `drop_slam0` 接近、固定交权、钩索校验和后台延迟是待验证机制，不能把其计数直接当成闭环失败归因。拆分的 25/47 是开环数，不等于闭环劈中率；静态覆盖高也不证明新路径能执行。
  2. **双怪 w13 没有当前数据。** 手头的基线（18/64、5/64、合并 23/128）和"头号死因是 Jump Aim 陷阱"都来自 10-18 的 b2 代码；之后 JUMPTRAP 改善了远跳陷阱，小符文损血升到 19。当前 h2 在 w13 的水平和损血原因排序都要重新测。
  3. **现成的终点价值现在用不上。** h2 开着 V2，规划器拿到的是 `V2Forecast` 包装，`_terminal()` 在 `f.__dict__` 里找不到 `_fc`，直接返回空：只开 `SSBOT_FORUM_TV=1` 等于没开。而且它的 `trapped` 只看候选终点后 4 个时刻的可达落点、不查路径，身体场只外推 0.3 s、不预测跳落和大符文，不能直接当"有没有退路"的判据。
  4. **测量不够判定。** 同一份代码两个时段 18/64 和 5/64；64 局一臂、无伤概率约0.18时，两臂独立比例差的95%半宽约13个百分点（不是单臂比例误差）；第0步已起草效果大小和非劣界限，尚待确认。
- **推荐顺序**（待你拍板，第 10 节）：第 0 步 测量协议 + 当前 h2 的 w13 基线 → 第 1 步的剩余部分和三个前置件（终点价值接线、审计适配层、闭环台架）→ 第 3 步 刀口行内联 → 第 2 步 终点价值 → 第 4 步 → 第 5 步（按需）。原来的"第 2 步先于第 3 步"撤回。

## 2. 硬约束（每一步都适用）

- **时间结构不动**：保留旧规划器的同步控制循环。四个量分开定门槛：控制线程（同步）、计算线程数（Numba，现为 4）、包络预算（deadline_ms）、总 tick 延迟（p50 / p99，现为 13.69 / 28.57 ms）。新东西不能让总 tick p99 变差超过事先定的界限。
- **不准出现提交、交接、兜底、后台 worker 发 Press。** 所有出刀都是同步 tick 里的普通候选行。
- **退路检查分三种结果：通过、失败、未检查。** 后两种都不算安全。检查要覆盖相关危险结束和钩索不可取消的阶段（现在只看终点后 24 帧）。
- **每个实验保存完整的有效配置（全部 `SSBOT_FORUM_*` 开关）和最终按键归属**（规划器还是哪个脚本）。分数变了不等于行为变了：脚本可以覆盖规划器选的键（`train/forum_planner_policy.py` 约 989 行）。
- **先离线、后实机。** 每一步一个闸门；闸门失败就停，等你决定，不在失败上继续往上盖。
- **一次只改一处**，同时和 h2、和上一阶段的配置配对比较。
- **每一步开工前写一页规格**：离线产出什么、每个 tick 做什么、闸门的判定标准（第 3 节）。你看过再开工作流。
- **每个阶段都审计**：掉血原因、漏掉的计划动作（没劈的锤、没打的 Idle）、开关之间的冲突，以及实际发出的按键的安全性（检查覆盖率、未检查的比例）。

### 3.2 每局口径与必存字段

- 起点用该局 `f_wake`，不后移到第一次攻击或受击；记录本波两个 Clapper 的 iid。战斗终点为两只均死亡、首次真实/记录的致死事件、或**120游戏秒**，取最早；击杀后的残余危险另记2游戏秒，若下一波激活则在激活前截止，不混入主指标。w7 的相同上限为60游戏秒。现有 `f_end`/`CLEAR` 不能直接代替“本波两只已死”。另设180墙钟秒上限；先触发它也计失败。
- `L`=窗口内真实 HP 损失之和，治疗不能抵消；用原始伤害事件及 HP 变化交叉核对，重复事件按事件帧/实体/事件标识去重。`T`=同一窗口内实际游戏时间 `sum(dt)`，不是墙钟时间，也不是 STATE数/60。零/缺失T属于测量错误。区分受击事件数与掉血量，禁止混用。
- 块 b 每臂的主指标 `R_b = 60 × sum(L) / sum(T)`；比较 `d_b = R_b(处理) − R_b(对照)`，各块等权。报告每时段及总块内差，不能先池化两臂全部分钟再相减。另报每局L、成功率、无伤清关率、每秒实际命中、实例/顺序效应。
- 击杀时间使用 **K\*=成功的游戏秒；失败一律记120秒**（w7记60），不只比较成功局。失败=未在上限内击杀两只，含死亡、would_die、开始战斗后的崩溃/断连。无伤清关必须同时成功且L=0。
- 锤按目标敌人进入 Slam Antic 的事件登记，键 `(episode,iid,entry_f)`；主劈锤率分母为其中存活并进入 Slam 0 的锤。劈中=该锤进入 Slam 0 后、离开其 Slam 0 前出现玩家 Down hit；提前打中前摇身体另列，不算劈锤。前摇中击杀导致取消的锤单列为成功的竞争结局，同时报“劈中或前摇击杀/全部前摇事件”，防止把快速击杀误算漏锤。未知/中断不冒充击杀。不得使用脚本 run 数当分母；旧44/46按新定义重算后才可比较。
- 每个tick保存 STATE帧/时间、接收与决策结束时间、计划和总tick耗时、最终mask/目标帧、按键归属、实际锁存键、脚本覆盖、退路“通过/失败/未检查”，以及截止/late/gap；归属覆盖率≥99.9%。STATE交付率≥99.9%；HP总量核对必须100%一致。缺口跨过事件时标未知，不猜测接受帧。旧日志没有的有效配置/归属字段是采集前置件，不能假称已经具备。

### 3.4 区间、样本量与分析冻结

- 统计单元是交叉块，不是tick或每次受击。以时段分层、整块有放回重采样 **20,000次**，固定分析seed **28100000**；区间取2.5%/97.5%分位数；实例效应先在块内跨标签求差，顺序效应比较每块两轮跨标签的均值差。A/A的多项区间是诊断线索，不将任一未校正显著结果单独称为已证实系统偏差，也不把“不显著”作为等效证明。正式结论以预注册的时段集合为范围，不将4个时段外推成“任意时间都稳定”。逐时段结果同时披露。
- 失败率和锤劈中率不能在稀疏/全零事件时用退化的bootstrap区间宣称精确。失败的处理/对照不一致块<5时，用保守上界 `U_98.75%(处理块中任一局失败的比例) − L_98.75%(对照块中两局均失败的比例)`，U/L为单侧Clopper–Pearson；它上界覆盖逐局失败率差。锤劈中不足20个含锤块，或bootstrap退化而仍要作非劣证明时，判证据不足，不放宽界限。此项可能决定正式样本量，64局不能保证通过。
- **量级核查，不当作新先导数据。** `C:/ssbot/data/m2_play/TWO_CLAPPER_OPEN_ITEMS.txt:55` 的SP14 JUMPTRAP A/B，每臂64局、受击次数/min差区间[-1.70,-0.01]，半宽0.845。粗略正态反推SE约0.431、32块的s约2.44；90%半宽约0.71，压到0.25约需每臂515局。原公式带1.25倍标准差保护约需292块，超过128块上限。它是b2受击次数、不是当前h2的HP损失，且原设计未必等同新交叉块，只用于排除明显不现实的预算。
- A/A不用于挑终点权重。取新的32块HP指标差标准差s，以 **σ=1.25s** 作设计标准差；第2步按设计真实改善 **δ=1.00 HP/min**、80%近似主指标功效：`B信号=((1.96+0.842)σ/δ)^2`，`B幅度=(0.842σ/(δ−0.50))^2`，`B主=ceil_to_4(max(32,B信号,B幅度))`。这是同时达到“上界<0”和“点估计≤−0.50”的正态近似；设计δ必须>0.50，真实改善恰为0.50时，点估计门槛的通过概率约只有一半。按上面的旧数据量级B主约76块（每臂152局），**不是已经选定的正式局数**；先导出来后以实际HP方差重新计算，并核对分层bootstrap下的功效。
- 正式 `B需求` 取主指标和各退化界需求最大值，在看处理结果前锁定。各非劣指标按“真实差0”设计，用 `((1.96+0.842)×1.25s_g/界限)^2`：HP/min退规则用0.25、L用0.25、失败率/锤率用0.05、p50用1ms、p99绝对差用2ms、gap比例用0.01；时间比/p99比使用对数比标准差和log(1.05)/log(1.10)。w7锤率没有先导方差时先采自己的先导，不能借w13。稀疏失败另取上述精确界所需块数；两臂零失败时至少86块，按4取整为88块（每臂176局）。非劣+0.25等界也可能超预算，不能因主指标可测就假设它们可测。先导数据不并入正式效果检验；功效估计是逐指标的，不保证联合过闸功效。
- **预算超限的处置。** 当前预算上限仍为128块/每臂256局，不能把计算结果直接截断为128后宣称80%功效。若 `B需求>128`，先不启动正式A/B：交付各指标所需块数、128块下可达到的功效/精度、总局数与时段成本；默认保留现行h2/上一阶段配置，转做测量降噪或其他不依赖该结论的离线工作。只有你同意扩大预算或改研究问题，才另写并冻结下一版预注册。若已按冻结B跑完仍未过界，结论为“未证实改善/非劣”，不是自动判定有害；保留原配置，不临时加样、不放宽门槛。增加样本或换方案须新协议、新正式数据。
- 多个权重/候选方案只能在开发集选一档，正式集只检验冻结的一档；失败后换档要用新的正式集。两对照及各门槛必须同时过，不挑最有利比较。

  1. 离线闭环：在闭环台架上，从每次锤的前摇起点出发，测劈中率。用一组没参与诊断和设计的锤作验收集（L2 和 SP14 的 132 次锤已用于开发）；"接近脚本"写成明确容差；退路检查"失败"或"未检查"的按键为 0。开环回放只能检查第一次按键之前的判断，不能当劈中率用。
  2. 然后上 w7 实机配对：关 SLAM_PLAY + CLAWSTRIKE（写明 `SLAM_PLAY_PREFS` 的取值），同时对 h2 和上一阶段的配置。看锤劈中率（按敌人的锤计）、每分钟掉血、击杀时间，不看无伤局数；确认前摇期不再退到 12.8 u。

## 7. 第 4 步：机会项、四条规则、按家族退规则

- **机会项**：在终点价值里给"能接上刀口"的终点加分。对每只 Clapper，按 L1 模型、随她的位置去枚举它的下一招（近招还是远招；跳是约 8.4 u 以外才出的远招，见 `forum_planner_plan.md`），再看从终点能不能赶上那一招的刀口格。要按她的位置枚举，不能对所有选择取并集，否则场又会饱和。
- **四条双怪规则**（你的原话，`forum_map_v2.md` 约 1304 行）：
  1. 站在两只之间；
  2. 在两只之间时，打离它身后那面墙更远的那只；
  3. 两只必须在同一侧时，把它们压进墙角，自己绝不被压；
  4. 两只离得远时，把焦点怪往中间赶。

  先把它们当检查用：在录下的双怪局面上看，终点价值是否偏好规则的选择。不一致说明缺机制或视野不够，到时再决定要不要写成打分项。
- **按家族退规则**，一次一族，每次在 w13 上同时对 h2 和上一阶段的配置配对，用事先定的非劣界限：

## 8. 第 5 步（按需）：递归表量化重建

- **触发条件**，两条都要满足：
  - 第 2 / 4 步的回放显示，可达模板（按终点类别的粗模板，看终点后 0.2 / 0.5 / 0.9 / 1.4 s，不带剩余冲刺、钩索硬直等状态）判错到影响选择，或者候选行明显漏掉了可行的刀口或退路；
  - 较小的修复不够：给模板加状态分类、加少量候选行之后仍达不到要求。
- **不为提速而做**：实机控制器不用递归表。它真正的用处是 1–2 s 的快速可达查询，给站位判断用。
- **方案要点**（Fable 5.1，10-26）：键量化（竖直相位、vx 分格、格点外 vy 分档、中途状态记成"动作 + 第几步"）；值带区间（内区间对格内每个成员都成立，外区间盖住所有成员）；地形不进键，每帧对高度区间做切割；可达、伤害、刀口三张表共用一套键。
- **离线验证**：可靠性（内 ⊆ 精确 ⊆ 外，0 违例）→ 封闭性 → 完备性损失 → 速度。开工前写明：热身集；封闭性统计的范围（520 局回放热身后新节点为 0，只证明这个集合上的经验闭合，不证明任意实机状态）；完备性损失的分母（235 个情境的验收集）；速度看哪些分位数；内存上限。
