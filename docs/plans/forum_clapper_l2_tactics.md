# Forum Clapper L2 战术设计与实现状态

更新：2026-11-06。源码基线：`9f6da15674da8c396d729a680f6868d47d9e233f`。范围为当前 w13 双 Clapper 的 B 臂开发路径。

**L2 已实现候选竞争，但战术意图、动作链和实机验收不是同一种完成状态。** 当前明确未实现的是：成团时“瞄准阶段贴砍，起跳后后撤，落地再回来砍”的完整第二分支，以及在它与后撤引导之间按空间选择的逻辑。返回中间已有代码和有条件的执行正例，持续空中下劈和双怪墙角突围仍未完成验收。

几何口径：怪的位置基准点只用于左右关系等判断；“两怪间可站空隙”指身体边缘之间的间隙，并需考虑英雄宽度及安全余量，不能用两个基准点的距离直接代替。

详细进度和实验规格以[主计划](forum_clapper_plan.md)为准。本页维护当前战术清单；后续修改原位更新对应条目，不把历史交付记录当作当前状态。

## 拟议设计 待用户审阅

**本节供用户先审阅。用户明确确认前，不向Opus派发Task182，不自动启动实现。当前Task181仅继续连续弹起与换目标的集成核验。**

### 三条硬要求

1. **英雄在两怪中间、一只怪瞄准起跳时，“留中间、钻跳怪、翻走路怪”三个分支的确定站位、适用判断、比较及路线选择，全部在瞄准阶段完成。** 正常执行不能等到瞄准锁定或怪已起跳才做三选一。瞄准锁定/起跳事件仅用于核对预期和推进已选路线。
2. **整个L2的所有战术条目都不设大黄蜂的空地准入要求。** 不限定当前必须 `GROUND`、必须 `AIR`，也不把这类门藏进候选的准备检查。具体动作可达性和落地完成确认归前台执行器/动作层；L2消费它们给出的预测，不另按当前空地状态筛掉战术。
3. **整个L2的所有战术条目都不设“大黄蜂当前能否输入”的准入要求。** 当前 `can.input` 或 `hero_accepting_input` 为假，不能直接否决候选，也不能通过准备检查间接加回这个门。L2应根据当前动作可合法交还的预计时刻、届时位置/速度范围，判断是否来得及完成战术；实际执行时的可输入检查及发键合法性仍归前台执行器/动作层，已承诺动作不能被强行打断。

### 瞄准阶段要确定什么

L2对每条候选分别考虑当前动作的合法交还时间、预计交还位置/速度范围及剩余瞄准时间，判断能否完成该分支的准备。使用计划中**瞄准时刻**的英雄位置及怪的朝向预测落点，不能把前摇第一帧的位置固定当作整招瞄准位置。留中间分支的靠近/引导在起跳怪面前完成，不能由一个统一的“引导位置”覆盖其他两条分支在走路怪处攻击的准备阶段。

以下三条都在瞄准期间完成计算和选择；方案同时写明瞄准期正在做的事及起跳后的目标。不能把起跳后的目标站位提前当成瞄准期间的准备站位。

| 分支 | 瞄准期间 | 起跳以后 | 适用与后续 |
|---|---|---|---|
| 留在中间 | **目标站位在前摇起跳那只怪的面前。** | **直接去砍走路怪，继续留在两怪中间。** 不等待跳怪落地或收招。 | 若预计中间能站人，优先选本分支；准备与后续攻击的目标对象分开记录。 |
| 钻跳怪 | **砍走路怪。** | 去跳怪预计落点背后、**不会被下落身体踩到的位置**。 | 中间站不下时参与比较；安全位置及钻行不能只按最终落点判断，须考虑斜向下降的身体扫掠。 |
| 翻走路怪 | **砍走路怪。** | **去走路怪头顶**，不是先翻到其外侧地面。 | 普通跳锤过后，可直接从头顶翻回中间；跳大符文时，在头顶多待一段或向外翻。后续条件提前写入方案。 |

钻跳怪时，怪是斜着下来的；跳跃距离很远时，下降轨迹可能很平。目标点即使位于预计落点背后，也不能据此认定不会被踩。L2选择的站位要避开相应时段的身体扫掠，具体钻行路径继续由动作层检查。

翻走路怪的头顶阶段与后续离开阶段分开表达。普通跳锤的攻击范围过去后，按已定方案翻回中间；大符文则按其后续覆盖决定继续在头顶停留，或向外翻，不能把两种招式统一处理成“锤子落地就回中间”。留顶/外翻的条件在瞄准期间写入方案，前台按实际事件推进，不在起跳后重新做三分支选择。

**方案在瞄准阶段就携带 `selected_branch`。** 前台不能在起跳时重新给三个分支报分择优。若实际落点、另一只怪的新招等超出原方案的支持范围，原方案失效，走通用保护并请求重算；这是异常变化的处理，不是把正常三选一推迟到起跳以后。

### 前台如何执行双阶段方案

| 执行阶段 | 使用的已有方案内容 | 前台维护的状态 |
|---|---|---|
| 瞄准准备 | 留中间：前摇起跳怪面前。钻跳怪/翻走路怪：砍走路怪。同时已有三个候选及选定去向。 | 当前动作的合法交还、是否已接近/到位、当前攻击目标、准备阶段是否失效。 |
| 起跳后去向 | 留中间：直接去砍走路怪。钻跳怪：去预计落点背后且避开下落身体。翻走路怪：去走路怪头顶，并带有普通跳锤/大符文的后续条件。 | 观察到锁定/起跳后推进执行；记录到达、动作结果、头顶停留/离开、完成或失效，不重新做三选一。 |

后台计算任务在执行前生成完整方案，算完就结束，不维护执行进度。工作进程可以常驻，等待下一次事件请求。前台规划器一侧的通用战术执行器维护运行状态；精确按键、命中/弹起和锤尾责任仍由原动作层处理。

### 方案和执行状态的通用格式

方案包含身份/代际、绑定招式实例、生成时刻与瞄准期限、有效时间/位置范围、阶段目标及攻击意图、三个候选及已选路线、推进/完成/失效/交还条件。执行状态另存当前方案和阶段、已处理事件、到位进度、等待/受阻/过期情况及待采用的新方案。格式保持小且通用，不在每个Clapper候选里另藏一套执行记忆，也不新造全游戏规则语言。

| 当前代码里的内容 | 新设计中的归属 |
|---|---|
| `takeoff` 的“起跳后换目标”规则 | 在方案中提前写明的事件分支；起跳时由通用执行器应用，不作为此时才开始选择的新战术。 |
| `departed`、是否已处理这次起跳 | 通用执行器的事件历史，用于防止同一事件反向换回。 |
| `intercept` 的背后来跳应答条件 | 方案的事件条件或触发重新生成的事件；不能直接删除而失去原有应答。 |
| `intercept_hold`、已经接谁及保持到何时 | 通用执行器的活动阶段和绑定实例。 |
| 独立拦截 `hold` | 执行中的继续/等待状态，不再以140分作为L2战术竞争。 |
| `middle_jump → hold` 无路线回退 | 条件不足/需重算结果，不能以95分空路线冒充已选好下一步，也不能无期限原地保持。 |

### 异步发布与验证

前摇等事件触发后台计算，同事件的重复请求合并；后台只发布完整方案，不改前台状态或发键。控制器收到每帧后非阻塞读取完成结果，核对实例、代际、有效期和计划支持范围，再在合法交还处采用。旧结果不能覆盖新方案，任何替换都不能改已发送前缀、挪用旧目标时钟或清掉旧怪锤尾责任。原建场进程/通信/双缓冲机制可以复用，但锁定前的新任务不能沿用原来只接受锁定后场景的入口。

验收要直接给出：瞄准锁定前已生成三候选并选定路线的记录；起跳后只执行已选路线的时间线；当前空地标志和当前可输入标志均不作为任一L2候选硬门的检查；以及晚到、乱序、实例变化、过期、交还和连续弹起换目标的有限生产路径证据。具体动作仍受原几何和发键检查，不能以取消L2空地/当前可输入门为由放宽动作合法性。

旧漏斗评分只在相应职责被接替并核实后关闭，不能因复用后台进程顺带删除其他场分量。本文确认前仅改设计，Task182维持待用户审阅；Task181及当前实机边界不变。

## 当前源码的大黄蜂空地条件

以下各表的空地条件是 **L2 自己在候选准入、路线选择或事件完成时检查的条件**。`GROUND`、`AIR` 取自大黄蜂的 `hero.contact.v`；“可输入”指 `hero.can.input is True`。**不筛空地**表示该处代码没有用大黄蜂当前的地面/空中状态作准入条件，不等于动作层已支持任意空中起点，其他场景、几何和事件条件仍须满足。

`middle/tight/left/right/over` 是身体水平范围推导的区域，均不要求大黄蜂落地；其中 `over` 也不是 `AIR` 的别名。共享几何另要求可信的位置、有效英雄身体框、墙界及两怪当前身体框，空中或冲刺中也可能因这些条件不满足而得到“几何未知”。

“地面站位”“空中站位”和 `side/stomp` 可以表示**要到达的位置或攻击意图**，不能反推大黄蜂当前姿态。怪的 `Jump/Air` 是怪的状态；成团路线代码里的 `grounded` 是另一只站着的怪，也不表示大黄蜂在地面。

## 当前源码的战术实现一览

下面按父场景列阶段和分支。代码中的规则标识不等于独立打法数量；旧后备入口也不单列成另一套完整战术。

### 保持焦点与处理新近程威胁

| 场景 | 当前实现 | 大黄蜂当前空地要求 | 验证范围 |
|---|---|---|---|
| 没有更高优先候选，继续打当前怪 | `keep` 已实现，保持焦点和接近攻击偏好。 | **不筛空地**；此候选也不先查英雄可输入。 | 现有基线；不保证怪永远不跳。 |
| 非焦点怪走到近处并开始近程招，换过去打它 | `near` 已实现，新近程前摇和距离满足条件才入池。 | **不筛空地**；近程距离按横向位置判断。 | 动作仍须满足踩头或平砍入口，不是看到前摇就强制换。 |

### 英雄在两怪中间且一只起跳

| 阶段或分支 | 当前实现 | 大黄蜂当前空地要求 | 执行与验证状态 |
|---|---|---|---|
| 瞄准阶段，能靠近起跳怪并为之后留出中间站位，就引导落点 | `middle_jump → guide` 已实现，另查瞄准时钟、剩余时间和站位窗口。 | **必须 `GROUND` 且可输入**；空中或接触/输入未知，L2直接返回 `hold`，不会生成 `guide` 交给执行器。 | 空中弹起中的引导未接入。 |
| 起跳后，中间仍能站人，贴站着怪平砍 | `middle_jump → stand` 已实现，依据已锁落点、攻击覆盖和站位窗口决定。 | **不筛空地**，也不先查可输入；地面是目的站位，不要求当前已落地。 | 输出地面站位和 `side` 意图，完整路径仍须通过动作层。 |
| 起跳后，中间站不下，候选路线一：钻跳怪 | `middle_jump → under` 查背后目的点、其他身体是否挡路，以及 `walk_fits` 横向时间估计，再与 `over` 比终点墙距。 | **不筛空地**；未因使用 `walk_fits` 就要求英雄接触地面，也未先查可输入。 | 横向估计不是空中路径验证，实际动作仍由动作层检查。 |
| 起跳后，中间站不下，候选路线二：翻走路怪 | `middle_jump → over` 声明远侧终点，另查目标状态、墙距及原前摇时钟。 | **首次声明须可输入，且接触为 `GROUND` 或 `AIR`**，同时满足现有接近时间上限。同事件、同目标已有 `over` 声明时，可暂时保持而不重过该准备条件；其他路线条件仍生效。 | 完整动作部分实现；声明远侧终点不等于已完成翻越和真实交还。 |
| 引导或起跳后路线条件不足，保持当前意图 | `middle_jump → hold` 是回退结果，仍作为 `middle_jump` 候选参与竞争。 | **没有统一空地要求**。空中导致 `guide` 被拒绝，只是生成 `hold` 的一种原因。 | 当前可按95分选中 `hold`；不自动改选翻怪，且不生成该中间事件的攻击入口。 |
| 绕行后选接下来攻击的怪 | 完整中间事件选择自身的目标；钻跳怪与翻站着怪可以选不同目标。 | 沿用所选路线的要求；这里没有新增的统一地面门。 | 与前面的路线选择属于同一父场景，不另算一套避跳打法。 |

中间事件本身在水平 `middle` 区域内、只有一只怪处于跳跃前摇或飞行时可建立，**建立事件不要求英雄在地面**；具体 `guide` 路线才有上述地面门。前摇分支返回 `hold` 时，不会在同一次路线选择中继续计算起跳后的 `stand/under/over`。已有 `over` 的有限交还保持也不另加英雄地面条件。

**“非焦点怪从背后跳来，钻过后接着打它”是这个起跳场景中的一种情况，但不能跳过中间能否站人的判断。** 代码还保留 `intercept/hold` 旧后备：`middle_jump` 未建立时，才可按背后来跳条件接成目标并保持；它本身主要指定目标，不能算已经检查了完整钻行。

`takeoff` 也是后备入口：没有中间跳跃上下文和拦截保持、英雄仍夹在两怪之间、当前焦点实际进入 `Jump/Air` 时，才可换另一只。中间事件存在时，`intercept/hold/takeoff` 不与它并行争夺该跳跃的处理。

| 后备规则 | 大黄蜂当前空地要求 | 对应代码含义 |
|---|---|---|
| `intercept`：接背后来跳的怪 | **不筛空地**，也不先查可输入。 | 根据怪的跳跃、朝向及英雄相对横向位置判断背后来跳；这里的飞行要求属于怪。 |
| `hold`：保持同一次拦截目标 | **不筛空地**，也不因英雄落地或升空而单独解除。 | 按怪的招式身份、跳跃/余圈结束或其他目标胜出解除；不同于上面的 `middle_jump → hold` 回退路线。 |
| `takeoff`：焦点起跳后换另一只 | **不筛空地**。 | “夹在两怪之间”是水平 `middle/tight`；几何未知时退回两怪基准点之间的判断，也不检查英雄高度或地面接触。 |

### 两怪成团并在英雄同一侧且一只起跳

| 完整战术或阶段 | 当前实现 | 大黄蜂当前空地要求 | 执行与验证状态 |
|---|---|---|---|
| 方案一前段：瞄准时后撤拉远 | `cluster_route → bait` 已实现；后撤目标为起点外侧约 2.5 个怪宽，受墙边限制。 | **不筛空地**，不先查可输入；建立事件看水平外侧区域和怪的状态。 | 那一盘没有完成有效距离标定，不能声称已经测出足够后撤多少。 |
| 方案一后段：观察到怪起跳，钻回站着怪前平砍 | 同事件由 `bait` 转为 `return`，指定另一只怪和 `side` 入口。 | **不要求英雄落地**；转阶段只看跳怪实际进入 `Jump/Air`，不会等待英雄 `GROUND`。 | 地面平砍是到达后的攻击意图，不代表已检查完空中返回或落地路径。 |

## 当前源码的分数竞争与互斥

整层复用公共候选选择器，不为每对战术单独新增选择器。完整战术决定是否适用及得分，公共部分统一处理比较、换目标成本和保持当前选择。战术内部“瞄准→起跳→落地”等事件阶段及已承诺动作的所有权继续按实际事件推进，不因采用公共竞争而每拍重选阶段。

只有满足入口条件的候选才参与比较：

`实际得分 = 战术最高分 × 适用度 − 换目标成本`

换目标默认扣 5 分，同分时偏向保持当前目标。最高分可通过 `L2Rules.clapper_scores` 覆盖，换目标成本由 `clapper_switch_cost` 控制。当前只有 `near` 使用连续适用度：`0.8 + 0.2 × max(0, 1 − 距离 / 8.05)`；其余已提供候选的适用度为 1，不适用时不入池。分数是偏好，不是成功概率。

| 规则标识 | 最高分 | 意义 |
|---|---:|---|
| `keep` | 50 | 继续当前焦点 |
| `intercept` | 130 | 接背后来跳的怪 |
| `hold` | 140 | 保持同一次跳跃的拦截目标 |
| `near` | 110 | 非焦点怪进入近程前摇 |
| `takeoff` | 90 | 焦点实际起跳后换另一只 |
| `middle` | 70 | 进入中间时选离墙远者 |
| `retreat` | 150 | 外侧撤离 |
| `flip` | 80 | 外侧近程招向内翻的意图 |
| `overhead` | 65 | 狭窄中间踩头意图 |
| `middle_jump` | 95 | 中间跳跃事件的引导、站位或绕行选择 |
| `bait` | 145 | 成团时拉远瞄准 |
| `return` | 145 | 成团怪起跳后钻回砍站着怪 |
| `back` | 70 | 近程招结束后返回中间 |

当前竞争仍有明确互斥和内部选择：

- `middle_jump` 先在内部按瞄准/起跳阶段选择 `guide/stand/under/over/hold`，再作为一个候选进入外层竞争。这些内部路线并非各自同时报分。
- 成团 `cluster_route` 生效时，外层只留下 `keep` 和这条路线的 `bait/return`，排除不兼容候选。空间不足不会自动产生尚未实现的贴砍分支。
- `back` 需要此前的近程威胁已结束，且没有当前中间跳跃、成团路线或拦截保持占着场景。它不是无条件最高优先级。
- 候选重新比较发生在敌人状态/实例、区域等事件变化时，以及默认每 6 个 L2 调用的周期点。L2 同步执行，不是每帧无条件切目标。

调低最高分可以抑制已入池的战术；调整分数不能让缺入口或被互斥排除的战术出现。

## 当前源码中L2与动作层的分工

L2 指定目标、站位意图，以及接近后偏向平砍还是踩头。换目标后，现有 `EntryAttack` 根据可站身体间隙和到达后的攻击窗口选择 `side/stomp`；特定战术也会明确指定。动作层负责按当前高度、距离、横向速度、资源、状态、输入前缀和危险决定能否完成。

各战术还共同经过以下输出处理，不能把这里的目的姿态或计分限制写成每条候选的当前空地门：
